## 2. 기본 동작이 달라진 것(0.7.1에서 올릴 때 주의)

1. **배열 → 구조체 요청은 기본이 "적용하지 않고 보고만"이다.** 변수 인덱스(`g_data[i]`)나 통째 사용(`Send(g_data)`)처럼 기계적으로 못 바꾸는 사용처가 하나라도 있으면 선언도 사용처도 바꾸지 않는다. 사용처 목록(`out/request_<id>_sites.md`)을 보고 처리 방법을 요청에 적어 다시 돌린다(3.2). 0.7.1은 일부만 바꿔 컴파일되지 않는 결과를 냈다.
   - 예전 키(`llm_variable_index`, `llm_other_uses`, `convert_declaration`)가 하나라도 있는 요청은 **예전처럼** 동작한다.
2. **sLLM 작업 수가 늘 수 있다.** 한 함수에 대상 100곳이면 0.7.1은 2건, 0.8.0은 13건이다. 대신 한 건이 실패해도 그 건의 8곳만 수동 검토로 간다(0.7.1은 100곳 전부).
3. **요청문 한 건이 다루는 줄 수의 상한(300)이 없어졌다**(`ask_max_sites` 기본 0). 양은 `--max-calls`로 조절한다.
4. **종료 코드 4**가 생겼다: 보내지 못한 작업이 대기로 남음. 0·1·2·3은 그대로다.
5. **수용 검사가 늘어 기각이 늘 수 있다.** 실제 모델에서 옳은 수정이 기각되면 3.5의 설정으로 끈다.
6. `_itoa` 등 16개 함수가 `R-T0-CRT-SECURE`에 더해졌고, 프로젝트에 `/sdl`이 켜져 있으면 프로젝트 점검에 나온다(3.7).

## 3. 기능별 설명

### 3.1 구조 분석 (`[M04 구조분석]`)

모두 컴파일러 없이 주석·문자열·전처리기를 가린 본문에서 괄호 짝과 `;`만 보고 판단한다.

| 함수 | 답하는 것 |
|---|---|
| `block_tree` | 중괄호 블록의 종류(함수, 클래스, 초기화 목록, if/for/while/switch 등)와 포함 관계. 표의 행은 블록으로 남기지 않는다(150만 자 표에서도 1초 안팎) |
| `ctrl_ranges` | 제어문의 범위(조건, 본문, else까지). 중괄호 없는 본문도 정한다 |
| `find_decl`, `lookup_decl` | 어떤 위치에서 쓰인 이름의 선언. 지역 → 인자 → 클래스 멤버 → 파일 범위 순서. 배열인지 포인터인지, 확정인지(`certain`) |

한계: 전처리기를 실행하지 않는다. 괄호를 숨긴 매크로, `#if`로 갈라진 문장, `for` 머리 안의 선언은 틀리거나 못 찾을 수 있다. 그런 곳은 "확정 아님"으로 다룬다.

### 3.2 배열·표 → 구조체

**요청 양식**

```json
{"id": "REQ-T", "type": "array_to_struct", "target": "LIMIT_TBL", "struct_name": "LIMIT_ROW_T",
 "mapping": {"COL_ID": "id", "COL_MIN": "min", "COL_MAX": "max"},
 "variable_index": "stop", "bare_use": "stop", "on_unresolved": "stop"}
```

| 키 | 값 | 뜻 |
|---|---|---|
| `variable_index` | `stop`(기본) | 변수 인덱스가 있으면 요청 전체를 적용하지 않는다 |
| | `manual` | 그곳만 수동 검토로 남기고 나머지를 적용한다(결과는 그곳을 고치기 전에는 컴파일되지 않는다) |
| | `llm` | sLLM에 맡긴다 |
| | `cast` | `((int*)&g_data)[i]`로 바꾼다(2차원은 `((int*)&TBL[r])[c]`) |
| | `raw_view` | 구조체와 배열을 공용체로 겹쳐 두고 `.raw[i]`로 쓴다 |
| `bare_use` | 위와 같음 | 이름이나 행을 통째로 쓰는 곳(`Send(g_data)`). `raw_view`는 `variable_index`도 `raw_view`일 때만 |
| `on_unresolved` | `stop`(기본) / `keep` | `llm`에 맡긴 곳이 실패했을 때. `stop`은 그 요청의 수정을 **전부 되돌린다**. `keep`은 남기고 "미완료"로 표시한다 |
| `allow_out_of_scope` | `true` | 처리 범위(`--only`) 밖 파일에 사용처가 있어도 진행한다 |
| `defined_in`, `function` | 경로, 함수 이름 | 같은 이름의 배열이 여럿일 때 대상을 한정한다 |

**사용처 분류.** 이름이 나온 곳을 전부 아래 가운데 하나로 분류한다. 분류한 수와 센 수가 다르면 적용하지 않는다.

선언 / 상수 인덱스 / 변수 인덱스 / 열 상수 / 열 변수 / 행을 통째로 사용 / 이름을 통째로 사용 / 메모리·입출력 함수의 인자 / 이름의 주소 / 지원하지 않는 꼴의 선언 / 요소 수 매크로 / sizeof(이름) / sizeof(행) / sizeof 안의 요소 / 다른 기호(같은 이름의 멤버·지역 변수) / 처리 범위 밖 파일

**적용하지 않는 경우**(하나라도 걸리면 아무것도 바꾸지 않는다): 선언을 구조체로 바꿀 수 없음, 범위 밖 파일에 사용처가 있음, 지원하지 않는 꼴의 선언이 있음, 변수 인덱스·통째 사용이 있는데 정책이 `stop`.

**큰 표.** 선언 머리(`static const int TBL[45000][6] = {` → `static const TBL_ROW_T TBL[45000] = {`)와 사용처만 바꾼다. 데이터는 읽기만 하고 한 글자도 바꾸지 않으며 sLLM에 보내지 않는다. 병합 때 큰 초기화 목록의 내용이 그대로인지 다시 확인한다.

**산출물**: `out/request_<id>_sites.md`(사용처 전수 목록. 적용했든 안 했든 나온다), 보고서 5절의 "변경 계약"(적용하지 않음 / 대기 중 / 미완료 / 결과가 어긋남), 검증 기록의 `E4`(병합 뒤 옛 접근 꼴이 예상보다 많이 남았는지).

**권하는 순서**: ① `--no-llm`으로 한 번 돌려 사용처 목록을 본다 → ② 변수 인덱스·통째 사용의 처리 방법을 정해 요청에 적는다 → ③ 다시 돌린다.

### 3.3 참고 영역과 작업 나누기

- 조각 밖에 있는 **변수 선언**을 `[참고: 선언]`으로, 조각 위에 있는 **감싼 구문의 머리**(if, for 등)를 `[참고: 감싼 구문]`으로 요청문에 붙인다. 타입이 패키지에 정의된 구조체면 그 정의도 붙인다. 참고는 고칠 수 없는 영역이다.
- 조각의 시작이 큰 초기화 목록 안이면 선언 머리까지 당긴다(머리가 잘리지 않게).
- 독립 수정(규칙 탐지, 요청문)은 작업 하나에 8곳·150줄까지만 넣는다. 결합 수정(분할 순차로 가는 큰 구간, 요청의 `coupling: coupled`)은 나누지 않는다.

| 설정(`limits`) | 기본 | 뜻 |
|---|---|---|
| `task_max_targets` | 8 | 작업 하나의 수정 지점 수. 0이면 나누지 않는다(0.7.1 방식) |
| `task_max_lines` | 150 | 작업 하나의 줄 수 |
| `ref_decl` | true | 참고 영역을 붙일지 |
| `ref_chars` | 1500 | `[참고: 선언]`의 글자 수 상한 |
| `ask_max_sites` | 0 | 요청문 한 건의 줄 수 상한(0은 없음) |

### 3.4 호출 예산, 대기, 이어서 실행

```
vupdate run --package D:\src\PKG_A --from-vs 2008 --to-vs 2022 --max-calls 200
vupdate run --resume <실행 폴더>            (남은 것을 이어서. --max-calls 를 다시 줄 수 있다)
vupdate status --run <실행 폴더>            (대기 이슈 수)
```

- `--max-calls N`: 이번 실행에서 sLLM에 보내는 호출 수의 상한. 다 쓰면 남은 작업을 **대기**로 두고 받은 응답까지만 반영한 결과를 낸 뒤 종료 코드 4로 끝난다. 보고서 첫머리에 "아직 끝나지 않은 실행"이라고 적힌다.
- 서버가 재시도 끝까지 바쁘다고 답한 작업(429, 503)도 수동 검토가 아니라 대기로 둔다. 연속 3건이면 그 뒤는 보내지 않는다.
- `--resume`: sLLM 주소는 처음 실행의 값을 물려받는다(열쇠는 저장하지 않으므로 환경변수나 설정에서 다시 읽는다). 받아 둔 응답은 실행 폴더의 캐시에서 다시 쓰고 **호출하지 않는다**. 예: 작업 13건을 5 + 4 + 4회로 세 번에 나눠 보내도 호출 합계는 13회다.
- 요청(배열 → 구조체)의 사용처가 대기 중이면 그 요청의 수정은 **결과에 넣지 않는다**(반쯤 바뀐 결과를 내지 않으려는 것). 이어서 실행해 다 고쳐지면 넣는다.
- 분할 순차로 나눈 구간도 같다. 뒤 조각이 대기로 남으면 이미 받은 앞 조각의 수정도 결과에 넣지 않는다. 이어서 실행할 때는 처음과 같은 경계로 나누므로 앞 조각을 다시 보내지 않는다.
- 수동 검토로 끝난 작업(형식 오류로 재요청 한도를 넘긴 것 등)은 이어서 실행해도 다시 보내지 않는다.

### 3.5 수용 검사 추가

sLLM이 낸 수정 블록이 형식과 위치 검사를 통과한 뒤에 본다.

| 검사 | 걸리면 | 끄는 설정(`limits`) |
|---|---|---|
| 선언 변화: 선언을 없앴는데 그 이름이 다른 줄에서 쓰임 / 새로 선언한 이름이 이미 선언돼 있음 | 기각하고 사유를 붙여 다시 요청 | `decl_change_check: false` |
| 크기 인자: 새로 쓴 `sizeof(이름)`, `_countof(이름)`의 이름이 포인터(확정) | 기각하고 다시 요청. 확정이 아니면 메모만 | `size_arg_check: false` |
| 새 이름: 조각·참고·지침·패키지 어디에도 없는 이름 | **기본은 기각하지 않고** 검토 메모만(`mark`). `reject`면 기각 | `new_name_check: "off"` |
| 중복 선언: 병합 직전, 수정으로 생긴 선언이 같은 블록에 두 번 | 뒤 수정을 뺌(수동 검토) | 없음 |
| 변경 범위: ① 함수 안 ② 파일 안(static) ③ 파일 밖에 영향 | 기록만. 보고서 7절의 "확인할 점" 열과 건수 | 없음 |

새 이름 검사를 `reject`로 두면 패키지에 없던 표준 함수(`fgets` 등)를 쓴 옳은 수정이 기각된다(시험에서 실제로 그랬다). 그래서 흔한 C·CRT·Win32 이름 170여 개를 내장했고, 사내 공용 함수는 `known_names`에 적는다. 기본값을 `mark`로 둔 이유다.

### 3.6 위치 조건, 찾기 전용, 문장 요청

**명시형 요청문의 꼬리표**(`--ask`, `--ask-file`, 요청 파일의 `asks`)

```
[if] WriteLog: 첫 인자로 __LINE__ 을 추가한다          if 문 안에서 쓰인 곳만
[loop, find] Sleep: 반복문 안에서 Sleep 을 부르는 곳   고치지 않고 목록만(out/found_ASK-2.md)
[string, find] /DSN=\w+/: 연결 문자열                  문자열 안에서만
```

위치: `if`, `for`, `while`, `loop`(for + while), `switch`, `string`, `comment`. 동작: `find`(찾기 전용. sLLM에 보내지 않고 수동 검토도 만들지 않는다).

**문장 요청**(`--say "문장"`, `--say-file`, 요청 파일의 `sentences`). 대상 이름을 적지 않아도 된다.

```
vupdate run ... --only "Src/Net/*" --until S5 --say "if 문 안에서 로그를 남기는 함수를 찾아 줘"
```

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 1 | 도구 | 문장에서 위치(if 문, 반복문, 문자열 …), 동작(찾기/수정), 영문 이름을 뽑는다. 이름이 패키지에 있으면 그것이 대상이고 여기서 끝난다. `A를 B로 바꿔줘`의 B는 대상에서 뺀다 |
| 2 | sLLM 1회 | 문장만 보내(코드는 보내지 않는다) JSON 한 줄을 받는다: 동작, 위치, 이름에 들어갈 영어 낱말(12개까지) |
| 3 | 도구 | 그 낱말이 **낱말 단위로** 든 호출 이름을 패키지에서 고른다(`log`로 `Dialog`를 잡지 않는다) |
| 4 | sLLM 1회 이상 | 후보를 `번호. 이름 (횟수) 예: 쓰인 줄`로 보내 `KEEP: 1, 4, 7`을 받는다(150개씩) |

- 모델이 내는 것은 낱말과 번호뿐이다. 대상 이름은 도구의 색인에서만 나오므로 없는 이름이 대상이 되지 않는다.
- 결과는 `out/request_resolved.json`에 명시형으로 남는다. 이 파일을 `--request`로 주면 해석을 다시 하지 않는다. `targets`를 사람이 고쳐도 된다.
- 해석하지 못한 문장(모델을 쓸 수 없거나, 형식이 두 번 틀리거나, 후보가 없음)은 수동 검토로 남는다.
- `--ask`에 대상 없는 문장을 주면 지금도 **공통 요청**이다(0.7.0 동작 유지). 문장 요청은 `--say`로 준다.
- 실제 코드(610만 자)에서 영향범위 단계까지 9초, 해석 호출 2회, 가장 큰 요청문이 5,619자였다(모의 모델).

### 3.7 규칙 보강

- `R-T0-CRT-SECURE`에 `_itoa`, `_ltoa`, `_ultoa`, `_i64toa`, `_ui64toa`, `_itow`, `_ltow`, `_ultow`, `_strlwr`, `_strupr`, `_wcslwr`, `_wcsupr`, `_mktemp`, `_ecvt`, `_fcvt`, `_gcvt`를 더했다(코드는 바꾸지 않고 `_CRT_SECURE_NO_WARNINGS`로 흡수).
- `.vcproj`의 `/sdl`, `.vcxproj`의 `SDLCheck`가 켜져 있으면 프로젝트 점검에 "SDL 검사(/sdl)" 항목이 나온다. `/sdl`은 C4996을 오류로 올리므로 위의 흡수가 통하지 않는다.
- 2017 이후 구간의 규칙 보강은 하지 않았다(실제 빌드 오류를 보고 정하기로 함).

## 4. 시험하는 방법

```
python vupdate.py selftest                         51항목(0.7.1과 같음)
python vupdate.py rules --test                     규칙 시험 예 30건
python tests\test_v080.py . %TEMP%\v080            0.8.0 시험 40항목(g++ 가 없으면 1항목은 건너뛴다)
```

실제 패키지에서는 이 순서를 권한다.

1. `--no-llm`으로 한 번: 배열·표 요청의 사용처 목록, 규칙 탐지 건수, SDL 항목을 본다.
2. `--only`로 파일을 좁히고 `--max-calls 20`: sLLM 응답이 실제로 수용되는지, 보고서 7절의 "확인할 점"에 무엇이 찍히는지 본다. `logs/llm/`에 요청과 응답 원문이 있다.
3. 기각이 많으면 사유를 본다(`logs/run.log`의 "수정 블록 기각"). 검사가 지나치면 3.5의 설정으로 끄고 알려 주면 된다.
4. `--resume`으로 이어서 보낸다.
5. 문장 요청은 `--until S5`로 `out/request_resolved.json`을 먼저 본다. `logs/llm/resolve_*.txt`에 해석 요청과 응답 원문이 있다.

## 6. 명세(문서 15)와 다르게 만든 것, 만들지 않은 것

**다르게 만든 것**

| 항목 | 명세 | 실제 |
|---|---|---|
| 구조체 정의의 위치 | 함수 머리 앞 | 선언 바로 앞(선언이 함수 안이면 함수 안) |
| 잔여 재탐지(E7)가 어긋날 때 | 요청을 되돌림 | 되돌리지 않고 보고서 첫머리와 수동 검토에 경고(검증 단계에서 되돌리면 다른 수정까지 흔들린다) |
| `sizeof` 안의 요소 | 있으면 적용하지 않음 | 요소 타입으로 기계 치환 |
| 정책 | stop, llm, cast, raw_view | `manual` 추가. 분류에 "요소 수 매크로" 추가 |
| 새 이름 검사(E2) | 기각 | 기본은 메모만(3.5의 이유) |
| 변경 범위 ③ | sLLM 수정이면 기각 | 기록만(헤더의 인라인 함수 수정까지 막게 된다) |
| 이어서 실행(D10) | 남은 작업만 보냄 | 전체를 다시 계획하고 받은 응답은 캐시에서 되살림(조각의 기준 위치가 어긋나지 않게) |
| 대기 중인 요청 | 명세에 없음 | 결과에서 빼 두었다가 이어서 실행 때 넣음 |
| 문장 요청의 입구 | `--ask` | `--say`(기존 `--ask`의 "대상 없는 문장 = 공통 요청"을 유지) |
| 초기화 목록의 모양 | 변환 조건 | 보고용(행 수·열 수가 선언과 다르면 경고) |

**만들지 않은 것**

- 평면 배열(레코드 간격 `stride`)의 변환. 요청에 `stride`가 있으면 "지원하지 않음"으로 적용하지 않는다.
- 열 타입을 바꿀 때의 값 범위 검사(E10), 기계 치환의 토큰열 비교(E12), 연쇄 수정(E13), 모델 재검토 호출(E15).
- 유형 사전(`config/types.json`, C9). 지금은 요청의 `coupling` 키만 있다.
- 이름 없는 요청의 전수 판별(C10. "모든 if를 switch로" 같은 요청). 요구사항 A1의 범위 밖이다.
- 구조체 변경 요청(`struct_change`)과 빌드 로그 대상의 재검토(B10, B11). 0.5.0 그대로다.
- 저장소 규칙의 "줄 단위 한국어 주석". 구획·함수의 목적 주석과 주요 줄의 주석만 있다.

**알려진 제약**

- 중복 선언으로 뒤 수정을 뺄 때, 두 수정이 같은 작업에서 나왔으면 앞 수정의 이슈도 수동 검토로 표시된다(수정 자체는 적용된다).
- `--max-calls`는 수정 요청에만 적용된다. 문장 요청의 해석 호출(문장당 2~수 회)은 세기만 한다.
- 문장 요청의 낱말 맞춤은 영어 이름 기준이다. 한글 로마자 표기 이름(`girok` 등)은 모델이 그 낱말을 내야 잡힌다.
