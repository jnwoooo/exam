## 1. 한눈에

| 무엇 | 0.9.3 | 0.10.0 |
|---|---|---|
| 전문 버퍼의 위치 접근 | 다루지 않음 | 기존 구조체의 필드와 위치·길이가 같은 접근을 필드 접근으로 바꾼다(`buffer_fields`) |
| 병렬 배열 | 다루지 않음 | 한 함수의 지역 병렬 배열을 구조체의 배열 하나로 바꾼다(`record_group`) |
| 두 작업의 관계 | - | 따로 한다. 버퍼를 구조체 변수로 통째로 바꾸지 않는다 |
| sLLM | - | 쓰지 않는다. 전부 규칙이다 |
| 요청문의 "배열 → 구조체"가 대상을 못 찾을 때 | 위치 없는 미처리 기록 | 구조 분석으로 넘긴다. 못 찾으면 이름마다 파일·줄을 남긴다 |
| 옛 변환기(열·요소 → 필드) | 문자열 배열을 글자 필드로, 레코드 번호를 필드 번호로 만들려 함 | 만들지 않는다 |
| 집계 | 없음 | 전문 문장과 병렬 묶음을 따로 센 표, `out/struct_scan.md` |

## 2. 전달받은 내용과 반영

| 전달받은 내용 | 반영 |
|---|---|
| 병렬 배열은 함수 지역 배열. 선언 뒤 `memset`, DTO에서 적재(복사 + 정수 대입). 인덱스는 클래스 멤버 | 지역 배열만 대상으로 했다. `이름[번호]`를 `묶음[번호].이름`으로 바꾸는 글자 치환이라 번호가 클래스 멤버여도 된다. `memset` 여러 개는 하나로 합친다 |
| 전문 버퍼는 유지하고 내부 필드 접근을 개선. 이미 겹쳐 보기 방식 | 버퍼, 전문 길이, 송수신 호출을 건드리지 않는다. 이미 있는 겹쳐 보기 포인터를 그대로 쓴다 |
| 겹쳐 보기와 캐스팅 일괄 추가는 구분 | 기본값에서는 캐스팅을 새로 넣지 않는다. 요청에 `cast: add`를 줄 때만 넣는다 |
| 이미 구조체 필드로 쓰는 송신 코드는 유지 | 건드리지 않고 수만 센다("이미 구조체 필드로 접근(유지)") |
| 숫자 위치·커서 처리를 기존 필드와 대응 | 위치와 길이가 기존 구조체의 필드와 같은 접근만 바꾼다. 새 구조체를 만들지 않는다 |
| 대응이 확인된 고정 구간은 로컬 구조체에 복사하는 방법도 사용 | 읽기만 하고 구조체의 끝까지 읽는 버퍼에 쓴다(3.2의 ②) |
| 서로 다른 전문 형식, 50/100바이트 헤더 변환이 섞여 있음 | 함수·버퍼 단위로 따로 대응시킨다. 배치가 맞는 구조체가 여럿이면 고르지 않고 후보를 적는다 |
| 실행 중에 정해지는 길이로 조립하는 유틸 | 바꾸지 않고 "길이 모름", "위치 모름"과 사유를 남긴다 |
| 두 작업을 "버퍼 전체를 전송 구조체로 교체"로 묶으면 안 됨 | 요청 유형을 둘로 나눴다. 통째 교체는 넣지 않았다 |

## 3. 전문 버퍼의 필드 접근 (`buffer_fields`)

### 3.1 읽는 것

함수의 문장을 순서대로 따라가며 버퍼 접근마다 (위치, 길이)를 계산한다.

| 읽는 것 | 예 |
|---|---|
| 숫자 인덱스, 포인터 위치 | `&pBuf[5]`, `pBuf + 37`, `pBuf[43] = 0x03` |
| 커서 증가(지역 정수 변수) | `nPos = 0; … nPos += 10;`, `nPos += sizeof(h->szLot);`, `buf[n++]` |
| 길이 | `memcpy`·`strncpy`·`memset`의 길이 인자, `sprintf` 형식의 폭, 요소 쓰기는 1 |
| 겹쳐 보는 포인터 | `MES_BODY* p = (MES_BODY*)pBuf;`, `(T*)(pBuf + 100)`, `LPMES_BODY p = (LPMES_BODY)pBuf;` |
| 구조체의 배치 | 모든 멤버가 `char` 계열이거나 `#pragma pack(1)` 안에서 정의된 구조체만 확정으로 본다. 안쪽 구조체는 풀어서 본다 |

### 3.2 바꾸는 경우

| | 조건 | 결과 |
|---|---|---|
| ① 기존 겹쳐 보기 포인터 | 그 함수에 버퍼를 구조체로 겹쳐 보는 포인터가 이미 있고, 접근의 위치와 길이가 필드와 같다 | `memcpy(pBuf + 37, szTmp, 6);` → `memcpy(pBody->szQty, szTmp, 6);` |
| ② 로컬 구조체 복사 | 겹쳐 보는 포인터가 없고, 버퍼를 읽기만 하며, 기존 구조체와 배치가 맞고, 그 구조체의 끝까지 읽는다 | `MES_INSP msg_pBuf;` 선언과 `memcpy(&msg_pBuf, pBuf, sizeof(msg_pBuf));` 한 줄을 넣고 `pBuf + nPos` → `msg_pBuf.szLot` |
| ③ 포인터 추가(`cast: add`일 때만) | ②가 안 되는 버퍼(쓰는 버퍼 등)이고 배치가 맞는 구조체가 하나다 | `const MES_HDR50* pmsg_pSrc = (const MES_HDR50*)pSrc;`를 넣고 `pSrc + 5` → `pmsg_pSrc->szSeq` |

- 커서 계산(`nPos += 10`), 반환값, 버퍼 선언, `memset(pBuf, ' ', 길이)` 같은 버퍼 전체 문장은 그대로 둔다.
- 요소 하나에 쓰는 문장은 그 글자를 품은 `char` 필드로 바꾼다: `pBuf[21] = 'X'` → `pBody->szLot[1] = 'X'`.
- ②의 복사 문장은 그 버퍼를 처음 읽는 문장 바로 앞에 넣는다. 선언은 함수의 첫 줄에 넣는다(C89에서도 컴파일된다).

### 3.3 바꾸지 않는 경우와 사유

`out/struct_scan.md`의 문장별 표에 사유가 적힌다.

| 사유 | 예 |
|---|---|
| 위치 모름 | 커서가 실행 중에 정해지는 길이만큼 늘어남, 분기에 따라 값이 다름, 반복 뒤, 커서가 지역 정수 변수가 아님. 값을 확신할 수 없으면 모름으로 둔다(3.5) |
| 길이 모름 | `memcpy(p + 100, src, nLen - 50)`, 길이를 모르는 보조 함수에 위치를 넘김 |
| 반복 안의 상대 위치 | 레코드를 되풀이해 쓰는 반복문 안의 접근 |
| 필드의 경계와 다름 | 20바이트 필드에 10바이트만 씀 |
| NUL이 필드 밖으로 나감 | `sprintf(pBuf + 10, "%05d", n)`. 멤버 접근으로 바꾸면 필드를 넘겨 쓰는 코드가 된다 |
| 대응 확인(바꾸지 않음) | 배치가 맞는 구조체는 찾았지만 겹쳐 보는 포인터가 없고 ②의 조건도 아니다. `cast: add`를 주면 바꾼다 |
| 배치가 맞는 구조체가 없음 / 여럿 | 여럿이면 후보 이름을 적는다. 요청의 `struct`로 정할 수 있다 |
| 겹쳐 보는 포인터가 보이는 범위 밖 | 포인터를 `if` 안에서 선언했고 접근은 그 밖에 있다 |

### 3.4 구조체를 고르는 조건(①이 아닐 때)

1. 위치와 길이가 필드와 같은 접근이 2곳 이상이다.
2. 구조체의 범위 안에서 필드의 경계와 어긋나는 접근이 없다.
3. 그런 구조체가 하나다.
4. 그 구조체의 정의가 이 파일에서 보인다(같은 파일, 직접·간접 include, 또는 이미 그 이름을 씀).

요청의 `struct`로 구조체를 정하면 1~3을 보지 않고, 맞는 접근만 바꾼다.

### 3.5 커서 값을 모름으로 두는 경우

커서 값을 잘못 알면 엉뚱한 필드로 바꾸게 된다. 그래서 다음 뒤에는 값을 모르는 것으로 둔다.

| 경우 | 예 |
|---|---|
| 분기에 따라 값이 다름 | `if (bLong) n += 5;` 뒤 |
| `switch` | `case`마다 `switch`에 들어올 때의 값에서 다시 시작한다. 앞 갈래에서 이어져 내려오면(`break` 없음) 모름. `switch` 뒤도 모름 |
| 반복 | 반복 안은 한 바퀴 안의 상대 위치로만 본다. 반복 뒤는 모름 |
| 변수를 다른 함수나 매크로에 그대로 넘김 | `Advance(n, 5);`, `STEP(n, 5);`. 참조 인자나 매크로가 값을 바꿀 수 있다(C 파일에서는 매크로만) |
| 변수의 주소를 넘기거나 포인터에 담음 | `Bump(&n);`, `int* pn = &n;`. 그 뒤로 그 변수는 따라가지 않는다 |
| `try` 블록, 읽지 않는 블록(`catch` 등) 뒤 | 안에서 바뀐 변수 |
| 레이블 뒤 | `goto`로 들어올 수 있다 |
| 읽지 못한 꼴의 대입 | `m = 1, n += 5;`, 세미콜론 없는 매크로 뒤에 붙은 문장 |

## 4. 지역 병렬 배열의 묶음 (`record_group`)

### 4.1 묶는 조건

- 같은 함수의 같은 블록에서 선언된 지역 배열이다.
- 첫 차원의 크기가 같다.
- 같은 번호 식(`[m_nIdx]`)으로 쓰인 곳이 있다.
- 1차원 `char` 배열끼리만 모인 것은 묶지 않는다(문자열로 본다).

### 4.2 바꾸는 것

```cpp
char szLot[MAX_ITEM][LEN_CODE + 1];     // 로트        struct BuildListRec
char szItem[MAX_ITEM][LEN_CODE + 1];    // 품목        {
int  nQty[MAX_ITEM];                    // 수량            char szLot[LEN_CODE + 1];  // 로트
                                                  →        char szItem[LEN_CODE + 1];  // 품목
memset(szLot, 0x00, sizeof(szLot));                        int nQty;  // 수량
memset(szItem, 0x00, sizeof(szItem));                  } stRec[MAX_ITEM];
memset(nQty, 0x00, sizeof(nQty));
                                                       memset(stRec, 0x00, sizeof(stRec));
strcpy(szLot[m_nIdx], dto.lot);                        strcpy(stRec[m_nIdx].szLot, dto.lot);
nQty[m_nIdx] = dto.qty;                                stRec[m_nIdx].nQty = dto.qty;
```

| 사용처 | 바꾼 꼴 |
|---|---|
| 선언 | 첫 선언 자리에 지역 구조체와 그 배열 하나. 나머지 선언은 지운다. 줄 끝의 주석은 필드 줄로 옮긴다 |
| 첨자 접근 `이름[번호]…` | `묶음[번호].이름…`. 번호가 변수, 클래스 멤버, 식이어도 같다 |
| 배열 전체를 0으로 지우는 문장들 | `memset(묶음, 0, sizeof(묶음));` 하나. 사이에 묶음과 무관한 문장이 있어도 된다 |
| `sizeof(이름) / sizeof(이름[0])` | `sizeof(묶음) / sizeof(묶음[0])` |
| `sizeof(이름)` | `(sizeof(묶음[0].이름) * (레코드 수))` |
| `= {0}`으로 초기화한 선언 | 묶음에 `= {0}` |

필드의 이름은 배열의 이름 그대로다. 변수는 `stRec`(헝가리안 표기가 없으면 `rec`), 구조체는 `함수이름Rec`이다. 요청의 `var_name`, `struct_name`으로 정할 수 있다.

### 4.3 막는 것

하나라도 있으면 그 묶음은 **하나도 바꾸지 않고** 사유와 줄을 남긴다.

| 사유 | 예 |
|---|---|
| 이름을 통째로 사용 | `SumQty(nVal, n)`, `p = szLot;`, 조건문 안의 `memset` |
| 묶음의 일부만 0으로 지움 | 5개 가운데 3개만 `memset` |
| 0이 아닌 초기화 목록, `const` 배열 | `int id[3] = {1, 2, 3};` |
| 묶음이 아닌 변수와 한 문장에 선언 | `char a[50][10], szTmp[32];` |
| 행 하나에 행보다 긴 길이를 줌 | `memset(szS[0], 0, sizeof(szS));`. 배열 전체를 이어진 메모리로 다루는 문장이라 묶으면 동작이 달라진다 |
| 이름이 매크로의 본문에 나옴 | `#define AT(i) szM[i]`. 매크로가 그 배열을 이름으로 가리킬 수 있다 |
| 다른 수정과 범위가 겹침 | 같은 자리를 규칙 수정이 이미 바꿈 |
| 바꾼 뒤에 옛 이름이 남음 | 분석이 놓친 사용처가 있다는 뜻이라 적용하지 않는다 |

파일 범위 배열과 구조체·클래스의 멤버 배열은 대상이 아니다. 전송용 구조체 안의 배열이 바뀌는 일은 없다.

## 5. 요청하는 방법

요청 파일(`--request`)의 `features`에 적는다. 예시는 `config/requests/EXAMPLE.json`에 있다.

```json
{ "features": [
    { "id": "REQ-BUF", "type": "buffer_fields" },
    { "id": "REQ-REC", "type": "record_group" }
] }
```

| 키 | 쓰는 곳 | 뜻 |
|---|---|---|
| `targets` | 둘 다 | 대상을 좁힐 이름의 목록. 함수, 버퍼, 배열, 구조체 이름이나 `Src/Net/*` 같은 파일 패턴. 없으면 탐지된 전체 |
| `apply` | 둘 다 | `false`면 탐지와 보고만 한다 |
| `cast` | `buffer_fields` | `existing`(기본) 또는 `add`(3.2의 ③을 켠다) |
| `struct` | `buffer_fields` | 대응시킬 구조체. 이름 하나, 또는 `{"함수 이름": "구조체 이름"}` |
| `var_name`, `struct_name` | `record_group` | 새 변수와 구조체의 이름 |

- 요청문(`--ask`)이 "배열 → 구조체" 의도로 분석되고 이름이 구조 분석의 대상이면 그것만, 일반 명칭뿐이면 탐지된 전체를 대상으로 한다. 요청 번호는 `ASK-1-1-buf`, `ASK-1-1-rec`다. 의도 분석은 모델에 달려 있으므로 확실하게 하려면 요청 파일을 쓴다.
- 결과를 먼저 보려면 `--until S5`로 돌려 `out/struct_scan.md`를 본 뒤 `vupdate run --resume 실행폴더`로 잇는다.
- `--only`로 처리 범위를 좁히면 그 범위의 파일만 본다.

## 6. 집계와 미처리 위치

보고서(`out/report.md`)의 "구조 분석" 절에 요청마다 한 줄이 나온다.

| 열 | 뜻 |
|---|---|
| 기준 | 코드에서 탐지한 전체. 전문은 상태별 문장 수, 묶음은 묶음·배열·사용처 수 |
| 요청 대상 | `targets`에 든 것 |
| 규칙으로 바꿈 | 방식별(전문), 종류별(묶음) 수 |
| sLLM 요청 | 항상 0건 |
| 실제 반영 | 병합·검증까지 남은 수정 레코드 수. 빠진 것이 있으면 따로 적는다 |
| 미처리 | 사유별 수. 표 아래에 `파일:줄 함수() 버퍼/묶음: 사유(줄 번호)` |

- 미처리는 함수·버퍼(또는 묶음)마다 수동 검토 이슈 하나로 `manual_review.md`에도 나온다. 파일과 줄이 있다.
- 바꾼 곳은 모두 "적용했지만 사람이 확인해야 하는 수정" 목록에 나온다.
- `out/struct_scan.md`: 버퍼별 문장 표(줄, 방향, 위치, 길이, 상태, 결과), 겹쳐 보는 포인터, 묶음별 제안 구조체와 막는 곳, 쓰인 구조체의 배치.

## 7. 옛 변환기(`array_to_struct`)에서 막은 것

요청문에서 온 배열 이름에만 적용한다. 요청 파일로 `mapping`을 직접 주면 전과 같이 한다.

| 경우 | 0.9.3 | 0.10.0 |
|---|---|---|
| `char 이름[N][L]`에 `이름[i][0]` 접근이 있음 | `char` 필드 L개짜리 구조체를 만듦 | "문자열의 배열로 보임". 만들지 않는다 |
| 1차원 배열을 숫자와 변수 인덱스로 같이 씀 | 숫자를 필드 번호로 삼음 | "레코드 번호로 보임". 만들지 않는다 |
| 배열 선언이 없는 이름 | "배열 MES 의 인덱스로…" | "이름 MES 의 배열 선언을 찾지 못함"과 코드에 나온 위치 |

## 8. 확인한 것

| 무엇 | 조건 | 결과 |
|---|---|---|
| 전달받은 꼴의 합성 예제(C++ 클래스, 함수 6개) | 기본값 | 전문 문장 28개 가운데 6개 변환(기존 포인터 2, 로컬 복사 4). 묶음 2개 가운데 1개 변환(수정 레코드 22건), 1개는 통째 사용으로 막힘 |
| 변환 전후의 동작 | g++로 컴파일해 실행 | 출력이 같다. `cast: add`의 결과도 같다 |
| 경계 조건(C 파일) | gcc `-std=c99`, `-std=c90 -pedantic-errors` | 둘 다 컴파일되고 출력이 원본과 같다 |
| 커서 값을 잘못 알 수 있는 꼴 14문장(3.5) | g++ | 순서대로 읽히는 4문장만 바꾸고 10문장은 그대로 뒀다. 출력이 원본과 같다 |
| 요청문 경로 | 모의 모델이 일반 명칭(MES, Data, TC)을 냄 | 요청 파일과 같은 결과. 모델 호출은 분석 1회 |
| 공개 코드(Notepad++ 610만 자, 함수 12,548개) | 두 요청, 전 단계 | 전문 위치 접근 39곳(함수 9개): 변환 0. 지역 묶음 7개: 1개 변환(배열 8개, 첨자 58곳), 6개는 초기화 목록·통째 사용으로 막힘. 읽지 못한 함수 0개. 전체 18초(요청 없이 7초) |
| 시험 | Linux | 자체 시험 50, 규칙 시험 33, `tests/` 10종 전 항목 통과(`test_v100.py` 49항목) |

공개 코드에서 바뀐 묶음 1개는 눈으로 읽어 확인했다(컴파일은 하지 못했다).

## 9. 하지 않은 것과 한계

| 항목 | 상태 |
|---|---|
| 포인터를 커서로 쓰는 꼴(`p += 5`), 보조 함수가 위치를 올리는 꼴 | 읽지 못한다. 그 버퍼는 표에 나오지 않는다 |
| 지역 변수가 아닌 커서(멤버, 전역, 참조 인자) | 따라가지 않는다. "위치 모름"으로 남는다 |
| `TCHAR` 버퍼 | 보지 않는다(글자 크기가 빌드 설정에 달려 있다) |
| 새 구조체 만들기 | 하지 않는다. 대응하는 구조체가 없으면 확정된 구간만 표에 적는다 |
| 위치 모름인 문장을 sLLM에 맡기기 | 하지 않았다. 이 판은 규칙만 쓴다 |
| 통째로 쓰는 곳이 있는 묶음을 sLLM에 맡기기 | 하지 않았다. 막힌 묶음으로 남는다 |
| 파일 범위 배열, 멤버 배열의 묶음 | 대상이 아니다. 탐지도 하지 않는다 |
| 매크로로 감싼 접근, 같은 이름의 다른 기호 | 글자 수준의 분석이라 구분하지 못할 수 있다. 바꾼 뒤 자체 확인(옛 이름이 남는지, 괄호 짝)에서 어긋나면 적용하지 않는다 |
| 다른 헤더에서 정한 `#pragma pack` | 알 수 없다. `char` 계열만 있는 구조체는 영향이 없고, 그 밖의 구조체는 같은 파일의 pack(1) 안에 있을 때만 쓴다 |
| 줄 단위 한국어 주석(저장소 지침) | 적용하지 않았다. 함수와 구획 단위로 목적 주석을 달았다 |

## 10. 실제 코드에서 볼 것

1. 요청 파일에 두 유형을 넣고 `--until S5`로 돌려 `out/struct_scan.md`를 본다.
2. 전문: 상태별 수와 "위치 모름"의 사유를 본다. "지역 정수 변수가 아님"이나 표에 아예 나오지 않는 함수가 많으면 9절의 읽지 못하는 꼴이다.
3. 전문: "대응 확인"으로 남은 곳이 바꿀 대상이면 `cast: add`를, 후보가 여럿이면 `struct`를 준다.
4. 묶음: 막힌 사유를 본다. "이름을 통째로 사용"은 그 호출을 사람이 고치거나 다음 판에서 다룰 대상이다.
5. 이어서 실행한 뒤, 바꾼 곳을 `out/diff/`와 보고서의 검토 목록에서 확인하고 cl로 빌드한다.
