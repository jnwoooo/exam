## 2. F1. 큰 상수 표 → 구조체 (140만~180만 자)

### 2.1 원칙

- 데이터(초기화 목록)는 모델에 보내지 않고, 다시 쓰게 하지도 않는다(D7).
- 바꾸는 것은 선언의 타입과 사용처의 접근 형태뿐이다. 초기값은 위치 순서로 채워지므로 선언만 바꿔도 유효하다.
- 그래서 송신 20k, 수신 3k의 한도와 데이터 크기는 관계가 없다.

### 2.2 다루는 모양

| 모양 | 선언 예 | 바꾼 선언 | 초기화 목록 |
|---|---|---|---|
| 2차원 표 | `static const int TBL[45000][6] = {{..},..};` | `static const TBL_ROW_T TBL[45000] = {{..},..};` | 그대로 |
| 평면 배열(레코드 간격 k) | `const int TBL[270000] = {..};` | `const TBL_ROW_T TBL[45000] = {..};` | 그대로(안쪽 괄호 없이도 유효. 검토 표시) |
| 1차원 배열(요소 1,024개 이하) | `int g[8] = {..};` | `G_T g = {..};` | 그대로(지금 있음) |
| 이미 구조체 배열 | `const ITEM_T TBL[N] = {{..},..};` | 필드 이름만 변경 | 그대로(구조체 변경 요청으로 처리) |

### 2.3 단계

| 단계 | 책임 | 하는 일 | 모델 토큰 | 실패하면 |
|---|---|---|---|---|
| 1 선언 찾기 | 도구 | 가린 본문에서 `타입 이름[행][열]`을 찾는다. 함수 안, 파일 범위, 헤더의 `extern` 모두. 크기가 이름이면 `#define`, enum에서 값을 찾는다 | 0 | 선언마다 타입이나 크기가 다르면 요청 전체를 수동으로 |
| 2 모양 확인 | 도구 | 행 수, 행마다 요소 수를 센다. 선언의 크기와 맞는지 본다 | 0 | 행을 매크로로 쓴 표처럼 셀 수 없으면 "모양 미확정"으로 수동 |
| 3 계약 | 도구(매핑이 없으면 모델 1회와 사람 확인) | 구조체 정의를 만든다. 필드는 열 순서, 타입은 요소 타입. 매핑에 없는 열은 `reserved_번호` | 0 (필드 이름 제안은 송신 1~2천, 수신 수백) | |
| 4 사용처 분류 | 도구 | 아래 2.4의 여섯 가지로 나누고 건수를 낸다 | 0 | |
| 5 적합성 판정 | 도구, 사용자 정책 | 기계적으로 못 바꾸는 사용처가 있으면 정책(2.5)대로 한다 | 0 | 정책이 "중단"이면 요청을 적용하지 않고 보고만 한다 |
| 6 적용 | 도구 | 선언만 교체한다. 데이터 구간은 건드리지 않는다. 정의는 감싼 함수의 머리 앞(헤더에 선언이 있으면 헤더)에 넣는다. 열 상수 접근을 필드로 바꾼다 | 0 | |
| 7 남은 사용처 | 모델 | 열 변수, 행 통째 사용을 지점 조각(F2)으로 보낸다. 참고 영역에 계약 발췌를 넣는다 | 곳당 1~3천 / 수백 | 기각 2회 뒤 수동 |
| 8 검증 | 도구 | 데이터 해시가 원본과 같은지. 병합 뒤 `이름[..][..]` 꼴이 남았는지 재탐지(E4). 괄호 균형. 가능하면 컴파일 검사 | 0 | 해시가 다르면 요청의 수정을 전부 되돌린다 |

### 2.4 사용처의 여섯 가지

| 분류 | 예 | 처리 |
|---|---|---|
| 열 상수 | `TBL[row][COL_MAX]` | 규칙: `TBL[row].max` |
| 열 변수 | `TBL[row][col]` | 정책(2.5) |
| 행 통째 사용 | `Send(TBL[row])`, `const int* p = TBL[row];` | 모델 또는 수동. 받는 쪽 타입이 바뀌므로 파일 사이 변경(F4)이다 |
| 이름 통째 사용 | `memcpy(dst, TBL, sizeof(TBL))`, `Dump(TBL)` | 메모리 함수는 그대로 유효. 그 밖은 모델 또는 수동 |
| `sizeof` 안 | `sizeof(TBL)/sizeof(TBL[0])` | 그대로. `sizeof(TBL[0][0])`처럼 둘째 인덱스가 있으면 수동 |
| 미확정 | 매크로나 별칭을 거친 접근 | 수동(E6) |

### 2.5 열 변수 접근의 정책

구조체는 `[col]`로 접근할 수 없어서, 이 사용처를 남기면 컴파일되지 않는다. 요청에 정책을 적는다.

| 정책 | 결과 | 장단점 |
|---|---|---|
| `stop`(기본) | 변환하지 않고 건수와 위치만 보고 | 안전하다. 사람이 방식을 정한 뒤 다시 실행한다 |
| `llm` | 곳마다 모델에 맡긴다(예: `switch(col)`로 필드를 고름) | 호출이 든다. 결과는 전부 검토 대상 |
| `cast` | 규칙: `((const int*)&TBL[row])[col]` | 모델 없이 끝난다. 필드 타입이 모두 같을 때만 허용한다. 표준 밖의 쓰임이라 검토 표시 |
| `raw_view` | 행 구조체를 공용체로 만들어 `TBL[row].raw[col]`로 치환 | 모델 없이 끝난다. 이름 없는 구조체는 컴파일러 확장이다 |

### 2.6 타입을 열마다 다르게 주는 경우

요청의 `types`로 열의 타입을 바꾸면 크기와 배치가 달라진다. 그때는 다음을 도구가 확인한다.
- 그 열의 값이 새 타입에 들어가는지 전 행을 훑는다(45,000행에 0.1초대). 넘치는 값이 있으면 좁히기 변환 오류가 나므로 요청을 거절한다.
- `sizeof`, 메모리 복사, 파일·통신으로 내보내는 사용처를 점검 목록으로 낸다(E5).

### 2.7 시험 코드로 확인한 것

| 항목 | 171만 자(행마다 한 줄, 45,000줄) | 135만 자(표 전체가 한 줄) |
|---|---|---|
| 모양 | 45,000행, 모든 행이 6개 | 같음 |
| 선언 | `static const int TBL[45000][6] =` → `static const TBL_ROW_T TBL[45000] =` | 같음 |
| 데이터 해시 | 원본과 같음 | 원본과 같음 |
| 사용처 | 열 상수 2곳 치환, 열 변수 1곳 남음 | 같음 |
| 걸린 시간 | 0.16초 | 0.14초 |

## 3. F2. sLLM 지점 수정의 조각 구성

`gets`, `sprintf` 계열, F1의 남은 사용처, 빌드 오류가 이 흐름을 탄다.

| 단계 | 하는 일 | 지금과 다른 점 |
|---|---|---|
| 1 편집 영역 | 대상 줄이 든 문장과 앞뒤 줄. 원문 그대로 | 시작과 끝을 문장 경계에 맞춘다. **생략 구간에 닿으면 그 문장의 시작(선언 머리)까지 당긴다**(P3) |
| 2 참고: 블록 머리 | 함수 머리, 대상을 감싼 if, for, switch의 머리 줄 | 지금은 함수 머리만 |
| 3 참고: 선언 | 대상 줄에 쓰인 이름마다 지역 선언 → 인자 → 파일 범위 → 패키지의 타입·매크로 순으로 찾아 붙인다 | 신규(P4). 찾을 때 생략 구간은 건너뛴다 |
| 4 참고: 계약 발췌 | 조각에 나온 이름에 해당하는 필드만. 나머지는 "필드 N개" 한 줄 | 지금은 정의 전체(P6) |
| 5 예산 | 1 → 4 순서로 넣다가 목표 예산에서 멈춘다. 한도 검사는 지금 식 그대로 | 지금은 줄 수 고정 |
| 6 호출 | 응답은 수정 블록, `NO_CHANGE`, `NEED_CONTEXT` | 그대로 |
| 7 수용 검사 | 지금 항목 + 아래 세 가지 | 신규 |
| 8 정의 보강 | `NEED_CONTEXT`가 오면 3번의 선언 찾기를 그대로 쓴다 | 지역 변수도 찾는다(P5) |

**편집 영역과 참고 영역의 차이**: SEARCH는 편집 영역의 글자에만 일치한다. 참고 영역은 요청문의 다른 구획에 들어가므로 모델이 고칠 수 없다. 참고 영역은 주석을 지우고 줄여도 된다(D12).

**7번에 더하는 검사**

| 검사 | 내용 | 막는 오류 |
|---|---|---|
| 새 이름 | REPLACE에 나온 이름이 조각, 참고, 지침, 패키지 어디에도 없으면 기각 | 없는 변수를 지어냄 |
| 선언 변화 | 수정 전후에 선언된 이름과 타입을 비교한다. 달라졌으면 그 이름을 함수 전체에서 다시 찾는다. 조각 밖에서 쓰이면 기각 | 조각 밖에서 쓰는 이름을 바꿈 |
| 크기 인자 | 버퍼 크기를 넣는 유형에서 `sizeof(이름)`의 이름이 포인터로 선언돼 있으면 기각 | `sizeof(ptr)` |

**시험 코드로 확인한 것**
- 조각 시작 당김: 45,010줄의 대상에서 앞 25줄이면 44,985줄(생략 구간 안)부터인데, 6줄의 선언 머리로 당겨 조각 첫 줄이 `static const int TBL[45000][6] = { /*생략*/ };`가 됐다.
- 선언 거꾸로 찾기: 45,015줄 함수에서 본 줄은 8개, 0.0003초였다. 함수 안에 없으면 인자 목록에서 찾는다.

## 4. F3. 같은 함수에 대상이 여럿일 때

| 항목 | 지금 | 개선 |
|---|---|---|
| 묶는 기준 | 30줄 이내면 한 작업 | 같은 함수 안에서, 예상 출력이 상한의 80% 안에 드는 만큼 한 작업으로 |
| 보내는 순서 | 전부 병렬 | 같은 함수의 작업은 차례로, 다른 함수는 병렬(동시 1~8) |
| 앞 작업의 결과 | 모른다 | 변경 내역을 다음 작업의 요청문에 붙인다(분할 순차의 방식 그대로) |
| 실패 | 작업마다 따로 | 따로. 분할 묶음처럼 전부 취소하지는 않는다(서로 독립인 수정이다) |
| 병합 뒤 | 검사 없음 | 같은 범위에 같은 이름이 두 번 선언됐는지 본다. 걸리면 뒤 작업의 수정을 기각 |

좌표는 지금처럼 규칙 수정까지 반영한 본문 기준으로 유지한다. 앞 작업의 수정으로 줄이 밀리지 않는다.

## 5. F4. 수정이 만드는 부작용

| 단계 | 하는 일 | 근거 |
|---|---|---|
| 1 분류 | 수용한 수정마다 전후의 선언을 비교한다. ① 함수 안 ② 파일 안의 선언 ③ 헤더·구조체·전역·매크로 | E2 |
| 2 ③의 허용 | 계약이 있는 요청(F1, 구조체 변경)에서 나온 것만 받는다. 그 밖의 ③은 기각 | E3 |
| 3 처리 순서 | 계약 → 헤더·타입 → 정의 → 사용처 | E3 |
| 4 잔여 재탐지 | 병합 뒤 패키지 전체에서 옛 이름과 옛 접근 꼴을 다시 찾는다. 남은 건수와 위치를 보고서 첫머리에 적는다 | E4 |
| 5 연쇄 | 남은 곳을 다시 보낼 때는 깊이 2까지. 그 뒤는 수동 | |
| 6 배치·크기 | 구조체 정의가 바뀌면 `sizeof`, 메모리 복사·송수신, `offsetof`, 패킹의 사용처를 점검 목록으로 | E5 |
| 7 보고 | 미해결이 남은 계약 변경은 "이 상태로는 컴파일되지 않는다"고 적는다 | F2 요구 |

동작이 같은지는 여기서도 보장하지 못한다. 빌드와 시험으로 확인하고, 오류는 `--build-log`로 다시 넣는다.

## 6. F5. 호출 예산과 이어서 처리

| 항목 | 지금 | 개선 |
|---|---|---|
| 작업 상태 | 수용, 수동 | 수용, 수동, **대기** |
| 요청문 상한 300곳 | 넘는 곳은 수동 | 없앤다. 실행 전에 대상 수와 예상 호출 수를 보인다 |
| 실행당 호출 예산 | 없음 | 옵션으로 받는다. 다 쓰면 남은 작업을 대기로 저장하고 다음 단계로 간다 |
| 서버가 계속 바쁨, 일일 한도 | 실패로 세어 수동 | 대기로 둔다 |
| 다음 실행 | 끝난 단계는 건너뜀 | 대기가 남았으면 sLLM 단계를 다시 열어 대기부터 보낸다. 받은 응답은 캐시에서 쓴다 |
| 결과 | | 대기가 남으면 보고서에 건수를 적고 종료 코드로 구분한다 |

계약 변경(F1)의 사용처가 대기로 남아 있으면 그 요청은 "미완료"로 표시한다. 사용처가 다 끝나야 컴파일되기 때문이다.

## 8. 확인하지 못한 것

- 실제 표의 모양. 2차원인지, 평면 배열인지, 이미 구조체 배열인지에 따라 2.2의 어느 줄을 타는지가 달라진다.
- 행을 매크로로 쓴 표, 중간에 `#if`가 든 표에서 모양 확인이 되는지.
- 실제 모델이 열 변수 접근을 쓸 만하게 고치는지, 선언을 보고 크기 인자를 옳게 넣는지.
- 시험 코드는 예제 몇 개로만 돌렸다. 매크로가 많은 실제 코드에서 선언 찾기의 적중률은 모른다.
