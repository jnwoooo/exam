# 0.10.4~0.10.5에서 달라진 것: 이름 없는 구조체가 있을 때 S5가 멈추던 결함 수정, 뺀 구조체의 기록

| 항목 | 내용 |
|---|---|
| 읽는 순서 | 30 |
| 작성일 | 2026-11-26 |
| 대상 코드 | `vupdate.py` 0.10.5 (1~4절은 0.10.4, 5절은 0.10.5) |
| 배경 | 0.10.3을 실제 코드에 돌리자 S5(영향분석)에서 `IndexError: list index out of range`로 멈춤 |
| 확인 범위 | Linux, 합성 예제와 공개 코드(Notepad++), 모의 sLLM. 실제 코드와 실제 gemma4에서는 확인하지 못했다 |

## 1. 증상과 원인

```
run_pipeline: STAGE_FUNCS[sid](ctx)
  ...
  out.sort(key=lambda x: (-x[0], x[1]["names"][-1]))
IndexError: list index out of range
```

- 멈춘 곳은 0.10.3에서 새로 넣은 함수 `_sx_llm_cands`다. 규칙이 위치나 길이를 확정하지 못한 접근을 sLLM에 보낼 때, 물음에 필드 표를 줄 구조체 후보를 고르는 자리다.
- 패키지에 **이름 없는 구조체**가 있으면 그 항목의 이름 목록이 비어 있다. 후보를 이름순으로 정렬하면서 마지막 이름을 꺼내다 오류가 났다.

```cpp
struct { char szTc[5]; char szLot[10]; } m_stLast;      // 이름 없는 구조체
typedef struct { char szA[3]; char szB[4]; } *PONLY;    // 포인터 별명만 있는 구조체
union { char raw[8]; struct { ... } part; } m_u;        // 이름 없는 공용체와 그 안의 구조체
```

- 조건: 이름 없는 구조체의 필드 이름 가운데 둘 이상이 그 함수에 나오고, 그 함수에 sLLM에 보낼 자리(위치 모름, 길이 모름)가 있을 때.
- 0.10.0의 규칙 쪽(`_sx_match`)은 이름 없는 구조체를 처음부터 건너뛴다. 0.10.3에서 새 함수를 쓰면서 같은 조건을 빠뜨렸다.
- 0.10.3의 시험과 공개 코드 확인은 이 경로를 지나지 않았다. 합성 예제에는 이름 없는 구조체가 없었고, 공개 코드는 sLLM을 끈 채로만 돌렸다.

S5에서 멈췄으므로 실행 폴더에는 `logs/run.log`, `state.db`, `out/preflight.md`만 남고 보고서와 변경 파일은 없다. 종료 코드는 2다.

## 2. 고친 것

| 무엇 | 내용 |
|---|---|
| 원인 | 이름 없는 구조체는 후보에서 뺀다. 물음에서 이름으로 가리킬 수 없기 때문이다 |
| 맞는 구조체가 이름 없는 것뿐일 때 | 그 자리는 sLLM에 보내지 않고 "필드 표를 줄 기존 구조체 후보가 없어 sLLM 에 보내지 않음"으로 남긴다 |
| 후보를 고르다 난 오류 | 실행을 멈추지 않는다. 경고를 남기고 그 함수의 남은 자리는 보내지 않는다 |
| 기록 단계의 오류 | 추적 파일(`ask_trace.md`), 집계 로그, 보고서의 "요청문 처리 추적"과 "처리 단계별 집계"를 만들다 오류가 나도 경고만 남기고 실행과 보고서는 끝까지 간다 |
| 보장 범위의 문장 | 만들다 오류가 나면 "보장 범위의 문장을 만들지 못했다"로 적는다. 예전의 고정 문장으로 되돌아가지 않는다 |
| 보내지 않은 이유의 문구 | "구조 분석 요청은 규칙으로만 처리함"을 0.10.3의 동작에 맞게 고쳤다(맡길 자리가 없었던 까닭을 적는다) |

수정 동작은 0.10.3과 같다. 멈추던 경우가 끝까지 도는 것만 달라진다.

## 3. 다시 돌릴 때

멈춘 실행 폴더는 새 판으로 이어서 돌릴 수 있다. 로그의 마지막 줄에 적힌 `--resume "실행폴더"`를 0.10.4로 실행한다. 처음부터 새로 돌려도 된다.

## 4. 확인한 것

- `tests/test_v104.py` 5개 항목. 같은 시험을 0.10.3에 돌리면 5개 모두 실패한다(앞의 3개는 같은 IndexError).
- 공개 코드(Notepad++, 구조체 항목 1,970개 가운데 이름 없는 것 16개)에서 sLLM을 켠 채로 구조 분석 요청을 돌려 끝까지 돌았다.
- 전체: selftest 50, 규칙 시험 33, 시험 파일 14종 모두 통과.

## 5. 0.10.5: 뺀 구조체를 로그와 결과 문서에 남긴다

0.10.4는 이름 없는 구조체를 후보에서 조용히 뺐다. 다른 후보가 있으면 뺐다는 사실이 어디에도 남지 않았다. 0.10.5는 뺄 때마다 적는다.

| 어디에 | 무엇을 |
|---|---|
| `logs/run.log` | `Src/Proc.cpp:5 CProc::Parse() 버퍼 pBuf: 이름 없는 구조체 Src/Def.h:9(필드 szTc, szLot) 를 sLLM 에 줄 구조체 후보에서 뺐습니다. 이름으로 가리킬 수 없기 때문입니다(typedef 나 태그로 이름을 붙이면 대상이 됩니다)` |
| 보고서의 "구조 분석" 절 | 같은 내용을 위치 목록에 한 줄로 |
| `out/struct_scan.md`의 접근별 결과 | 보내지 못한 사유 뒤에 "필드 이름이 맞는 구조체는 있으나 이름이 없다: Src/Def.h:9(...). 이름을 붙이면 대상이 된다" |

- 적는 것은 **이름만 있었으면 후보였던 구조체**다. 그 함수에 필드 이름이 둘 이상 나오는 것, 또는 위치와 길이가 맞는 것이다. 관계없는 이름 없는 구조체까지 적지는 않는다.
- 구조체는 이름이 없으므로 정의의 파일과 줄, 앞의 필드 몇 개로 가리킨다.
- 규칙 쪽(0.10.0부터 이름 없는 구조체를 건너뛰던 자리)도 같이 적는다. 위치와 길이가 맞는 구조체가 이름 없는 것뿐이면 사유가 "위치와 길이가 맞는 기존 구조체가 없음(배치가 맞는 구조체는 있으나 이름이 없어 쓰지 못함: ...)"으로 나온다.
- 같은 자리에서 같은 구조체를 뺀 로그는 한 번만 적는다.

이름 없는 구조체를 대상으로 삼으려면 원본에서 이름을 붙여야 한다(`typedef struct { ... } NAME;` 또는 `struct NAME { ... }`). 도구는 원본을 고치지 않으므로 이름을 대신 붙이지 않는다.

확인: `tests/test_v104.py`에 4개 항목을 더해 9개. 전체 시험 통과.
