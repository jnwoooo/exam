# 옵션별 사용 예시(0.10.0)

| 항목 | 내용 |
|---|---|
| 읽는 순서 | 23 |
| 작성일 | 2026-11-26 |
| 대상 코드 | `vupdate.py` 0.10.0 |
| 원본 | 이 문서의 표는 `vupdate examples --md`의 출력이다. 도구 안의 표(`USAGE`)가 원본이고, 시험(`tests/test_v092.py`)이 표의 명령을 모두 돌려 본다 |
| 확인 범위 | 표의 명령 65개가 명령줄 형식에 맞는지, 실행할 수 있는 것은 실제로 돌려 입력 오류가 없는지를 Linux에서 확인했다. 서버 점검(`llmcheck`)과 자체 시험(`selftest`)은 형식만 확인했다 |

옵션마다 실제로 쓰는 경우를 한 줄씩 적었다. 옵션끼리의 조합을 모두 늘어놓지 않고 **기본 명령에 그 옵션 하나를 더한 꼴**로 적는다. 옵션은 서로 독립이어서 필요한 것을 이어 붙이면 된다. 함께 써야 뜻이 있는 것만 마지막 절에 따로 모았다.

같은 내용을 도구에서 바로 볼 수 있다.

```
vupdate examples
```

## 1. 옵션별 예시

아래 표의 "기본"은 이 명령이다.

```
vupdate run --package D:\src\PKG_A --from-vs 2010 --to-vs 2022
```

### 대상

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--package` | 필수 | `기본` | 처리할 패키지 폴더. 원본은 읽기만 하고 결과는 실행 폴더의 out/ 에 쓴다 |
| `--out` | 결과를 둘 곳 지정 | `기본 --out D:\work\runs` | 실행 폴더를 만들 위치. 주지 않으면 지금 폴더의 runs |
| `--only` | 일부만 처리 | `기본 --only Src/Net/*` | 패키지 기준 경로의 와일드카드. 범위 밖 파일은 탐지도 수정도 하지 않는다 |
| `--only` | 범위 여럿 | `기본 --only Src/Net/*,Src/Ui/*` | 쉼표로 잇거나 옵션을 여러 번 준다 |
| `--exclude` | 일부를 뺌 | `기본 --exclude ThirdParty/*` | 외부 라이브러리, 생성된 코드, HMI 스크립트 폴더 등을 뺄 때 |

### 환경값

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--from-vs, --to-vs` | 필수 | `기본` | 2005, 2008, 2010, 2012, 2013, 2015, 2017, 2019, 2022 가운데 원본과 대상. 대상이 원본보다 뒤여야 한다 |
| `--cpp-standard` | C++17 로 | `기본 --cpp-standard c++17` | c++14(기본), c++17, c++20, c++latest. 대상이 2015 이상일 때만 뜻이 있다 |
| `--cpp-standard` | C++20 으로 | `기본 --cpp-standard c++20` | c++20 이상이면 준수 모드가 함께 켜진다 |
| `--from-cpp-standard` | 원본이 이미 C++17 | `기본 --cpp-standard c++20 --from-cpp-standard c++17` | 원본에서 이미 겪은 언어 표준 규칙을 끈다 |
| `--platform` | x64 로 전환 | `기본 --platform x64` | keep(기본), x86, x64. x64 면 64비트 규칙이 켜진다 |
| `--platform` | x86 을 명시 | `기본 --platform x86` | 프로젝트 설정 안내에 x86 을 적는다. 64비트 규칙은 켜지지 않는다 |
| `--conformance` | 준수 모드 켬 | `기본 --conformance on` | off(기본), on. on 이면 /permissive- 에서 걸리는 규칙이 켜진다 |
| `--charset` | 유니코드로 전환 | `기본 --charset unicode` | keep(기본), mbcs, unicode |
| `--charset` | MBCS 를 명시 | `기본 --charset mbcs` | 프로젝트 설정 안내에 멀티바이트를 적는다 |
| `--deprecated` | POSIX 이름을 코드에서 고침 | `기본 --deprecated fix` | suppress(기본): 설정으로 경고를 끈다. fix: strdup -> _strdup 처럼 이름을 고친다 |
| `--from-os, --to-os` | OS 판 올림 | `기본 --from-os "Windows 7" --to-os "Windows 11"` | 선택. sLLM 요청의 [환경]과 보고서에 들어가고, 낮은 WINVER 를 대상 OS 의 값으로 올린다 |
| `--to-os` | 대상 OS 만 | `기본 --to-os "Windows Server 2022"` | 원본을 모르면 대상만 줘도 된다 |
| `--from-db, --to-db` | DB 판 올림 | `기본 --from-db "Oracle 11g" --to-db "Oracle 19c"` | 선택. sLLM 요청의 [환경]과 보고서에 들어간다 |

### 요청

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--ask` | 요청 하나 | `기본 --ask "WriteLog 호출에 줄 번호 인자를 추가한다"` | 형식 없이 글로 적는다. sLLM 이 의도별로 나누고 도구가 대상을 찾는다 |
| `--ask` | 한 글에 여러 일 | `기본 --ask "g_data 배열을 구조체로 바꾸고, 주석의 문구는 바꾸지 않는다"` | 수정, 배열 → 구조체, 조건이 섞여 있어도 된다 |
| `--ask` | 찾기만 | `기본 --ask "strtok 을 쓰는 곳을 찾아 목록으로 낸다"` | 고치지 않고 out/found_*.md 에 목록만 낸다 |
| `--ask` | 요청 둘(따로 분석) | `기본 --ask "WriteLog 호출에 줄 번호 인자를 추가한다" --ask "g_data 배열을 구조체로 바꾼다"` | 옵션을 여러 번 주면 각각 따로 분석한다 |
| `--ask-file` | 긴 요청문 | `기본 --ask-file D:\work\asks.txt` | 파일 전체가 요청 하나다. # 으로 시작하는 줄은 뺀다 |
| `--request` | 요청 파일 | `기본 --request D:\work\request.json` | 배열 → 구조체의 필드 이름을 직접 정할 때 등. 형식은 config/requests/EXAMPLE.json |
| `--request` | 전문 버퍼의 필드 접근 | `기본 --request D:\work\request.json` | features 에 {"type": "buffer_fields"}. 버퍼의 위치 접근(숫자 인덱스, 포인터 위치, 커서 증가) 가운데 기존 구조체의 필드와 위치·길이가 같은 것을 필드 접근으로 바꾼다. 버퍼와 전문 길이는 그대로다. 규칙만 쓴다 |
| `--request` | 지역 병렬 배열의 묶음 | `기본 --request D:\work\request.json` | features 에 {"type": "record_group"}. 한 함수에서 같은 레코드 번호로 함께 쓰는 지역 배열을 구조체의 배열 하나로 바꾼다. 규칙만 쓴다 |
| `--ask` | 전문 버퍼와 병렬 배열(이름 없이) | `기본 --ask "전문 버퍼의 위치 접근과 병렬 배열을 구조체로 개선한다"` | 배열 → 구조체 의도로 분석되면 구조 분석이 탐지한 전체를 대상으로 한다. 확실하게 하려면 요청 파일로 준다 |

### 환경 호환성 항목의 처리 깊이

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--compat-llm` | 1 (기본) | `기본 --compat-llm 1` | 기계적 변경만 한다. 규칙의 수정과 설정 처리까지다. 규칙이 못 고치는 것은 수동 검토 목록에 올린다. sLLM 을 부르지 않는다 |
| `--compat-llm` | 2 | `기본 --compat-llm 2` | 1 에 더해, 선언을 읽어 판정하는 기계적 변환까지 한다(지역 char 배열에 쓰는 strcpy, strcat, sprintf 를 보안 CRT 함수로). sLLM 을 부르지 않는다. 조건은 22_추가_0.9.3.md |
| `--compat-llm` | 3 | `기본 --compat-llm 3` | 2 에 더해, 기계적 변경 뒤에 남은 항목 가운데 고치지 않으면 컴파일되지 않는 것(없어진 gets, x64 의 SetWindowLong 등 5개 규칙)을 sLLM 에 보낸다 |
| `--compat-llm` | 3 에서 보안 CRT 변환만 뺌 | `기본 --compat-llm 3 --disable-rule R-T2-CRT-SECURE-LOCAL` | sLLM 에는 보내되 2단계의 보안 CRT 변환은 하지 않는다 |

### sLLM 서버

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--llm-endpoint` | 주소를 명령줄로 | `기본 --llm-endpoint http://10.0.0.5:8000/v1` | 주지 않으면 환경변수 VUPDATE_LLM_ENDPOINT, 그다음 서버 설정의 값 |
| `--server-config` | 서버 설정 파일 | `기본 --server-config D:\work\server.json` | 주소, 토큰 한도, 허용 동시 수 등. 주지 않으면 config/server.json |
| `--max-parallel` | 동시 요청 수 | `기본 --max-parallel 4` | 1~8. 서버 설정의 허용 동시 수를 넘지 못한다 |
| `--max-calls` | 호출 수 상한 | `기본 --max-calls 200` | 다 쓰면 남은 작업을 대기로 두고 종료 코드 4 로 끝난다 |
| `--no-llm` | sLLM 없이 | `기본 --no-llm` | 규칙 수정만 한다. sLLM 대상은 수동 검토로 간다(요청문도 분석하지 못한다) |

### 규칙

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--rules` | 추가 규칙 파일 | `기본 --rules D:\work\rules.json` | 제품별 변경을 규칙으로 더할 때. 주지 않으면 config/rules.json 이 있을 때 그것 |
| `--disable-rule` | 규칙 하나 끔 | `기본 --disable-rule R-T2-WINVER-OLD` | 규칙 ID 는 vupdate rules 로 본다 |
| `--disable-rule` | 여럿 끔 | `기본 --disable-rule R-T2-WINVER-OLD,R-T1-TR1-NAMESPACE` | 쉼표로 잇거나 옵션을 여러 번 준다 |
| `--exceptions` | 예외 파일 | `기본 --exceptions D:\work\exceptions.json` | 끌 규칙, 제외할 파일과 줄, 프로젝트 고유 매크로. 형식은 config/EXAMPLE_exceptions.json |

### 실행 제어

| 옵션 | 경우 | 명령 | 뜻 |
|---|---|---|---|
| `--dry-run` | 탐지만 | `기본 --dry-run` | S0~S2 만 하고 보고서를 낸다. 무엇이 걸리는지 먼저 볼 때 |
| `--until` | 규칙 적용까지만 | `기본 --until S4` | sLLM 을 부르기 전에 멈춘다 |
| `--until` | 요청문 분석까지만 | `기본 --until S5` | out/ask_plan.json 으로 요청이 어떻게 나뉘었는지 확인한 뒤 --resume 으로 잇는다 |
| `--resume` | 이어서 실행 | `vupdate run --resume D:\work\runs\PKG_A\20261126_093000` | 대기로 남은 작업이나 --until 로 멈춘 실행을 잇는다. 받아 둔 응답은 다시 묻지 않는다 |
| `--resume` | 예산을 다시 주고 이어서 | `vupdate run --resume D:\work\runs\PKG_A\20261126_093000 --max-calls 200` | --max-calls 는 이번 실행에서 새로 보낼 호출 수다 |

## 3. PowerShell 스크립트(`Invoke-VersionUpdate.ps1`)의 매개변수

옵션 이름의 낱말 첫 글자를 대문자로 쓴 것이다. 값은 같다.

| 명령줄 | PowerShell | 비고 |
|---|---|---|
| `--package`, `--out` | `-Package`, `-Out` | |
| `--only`, `--exclude` | `-Only`, `-Exclude` | 여럿이면 쉼표로 |
| `--from-vs`, `--to-vs` | `-FromVs`, `-ToVs` | |
| `--cpp-standard`, `--from-cpp-standard` | `-CppStandard`, `-FromCppStandard` | |
| `--platform`, `--conformance`, `--charset`, `--deprecated` | `-Platform`, `-Conformance`, `-Charset`, `-Deprecated` | |
| `--from-os`, `--to-os`, `--from-db`, `--to-db` | `-FromOs`, `-ToOs`, `-FromDb`, `-ToDb` | |
| `--ask`, `--ask-file`, `--request` | `-Ask`, `-AskFile`, `-Request` | `-Ask`는 여러 개를 쉼표로 줄 수 있다 |
| `--compat-llm 1\|2\|3` | `-CompatLlm 1\|2\|3` | 0.9.1까지는 값 없는 스위치였다. 단계의 뜻은 `22_추가_0.9.3.md` |
| `--llm-endpoint`, `--max-parallel`, `--max-calls`, `--no-llm` | `-LlmEndpoint`, `-MaxParallel`, `-MaxCalls`, `-NoLlm` | |
| `--disable-rule`, `--exceptions` | `-DisableRule`, `-Exceptions` | |
| `--dry-run`, `--until`, `--resume` | `-DryRun`, `-UntilStage`, `-Resume` | |
| `--no-compile`, `--compile-parallel`, `--vs-path`, `--sdk-path` | `-NoCompile`, `-CompileParallel`, `-VsPath`, `-SdkPath` | |
| `--rules`, `--server-config` | 없음 | `config/rules.json`, `config/server.json`을 쓴다 |

PowerShell 스크립트는 Windows에서 실행해 확인하지 못했다.
