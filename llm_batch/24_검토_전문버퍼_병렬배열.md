# 실코드 시험 2차: 배열 → 구조체 요청의 실패 분석과 검토사항 판단

| 항목 | 내용 |
|---|---|
| 읽는 순서 | 24 |
| 작성일 | 2026-11-26 |
| 대상 코드 | `vupdate.py` 0.9.3 (**이 문서로 코드를 바꾸지 않았다**) |
| 배경 | 실제 코드에 "MES 배열 → 구조체 개선"을 요청한 결과가 모두 미처리로 끝남. 원인 정리와 검토사항 5개가 전달됨 |
| 확인 범위 | Linux, 합성 예제, 모의 sLLM, gcc. 실제 코드, 실제 gemma4, Windows의 cl에서는 확인하지 못했다 |

재현에 쓴 예제는 전달받은 설명에 맞춰 만든 합성 코드다. 실제 코드의 꼴이 다르면 수치가 달라진다.

> 이 문서는 0.9.3을 검토한 것이다. 그 뒤에 실제 코드의 꼴을 더 전달받아 0.10.0에서 다음과 같이 반영했다. 전문 버퍼는 새 구조체를 만들지 않고 **기존 구조체의 필드**에만 대응시키며, 캐스팅은 기본값에서 넣지 않는다(이미 있는 겹쳐 보기 포인터를 쓰거나 읽기 전용 구간을 로컬 구조체에 복사한다). 병렬 배열은 파일 범위가 아니라 **함수 지역 배열**을 대상으로 했다. sLLM은 쓰지 않는다. 이 문서의 시제품 스크립트는 구현으로 대체됐다. 지금의 동작은 `25_추가_0.10.0.md`가 맞다.

---

## 1. 결론

- 전달받은 실패는 0.9.3에서 **전부 재현됐다.** 모델의 답 문제가 아니라 도구의 설계 범위 문제다(2절).
- 지금 변환기는 "배열 하나의 요소(1차원)나 열(2차원)을 새 구조체의 필드로" 바꾸는 기능 하나다. 요청하신 것은 (1) 전문 버퍼의 바이트 구간을 필드에 대응시키는 일, (2) 병렬 배열 여러 개를 레코드 하나로 묶는 일이어서 종류가 다르다(3절).
- 검토사항 5개는 모두 타당하다. 시제품으로 본 범위에서 탐지와 변환의 대부분이 **규칙(기계적)으로 된다.** sLLM은 규칙이 못 정하는 곳에만 쓰면 된다(4절).
- 한 가지는 다르게 본다. 배열 후보를 못 만들었을 때 **일반 수정 경로로 넘기는 것은 권하지 않는다**(4.2).
- 전송용 구조 내부의 배열은 말씀대로 묶어서 바꿀 수 없다(4.5).
- 보고에 없던 것 하나: 지금 변환기는 조건이 맞으면 **뜻이 틀린 변환을 만들려 한다**(2절의 6, 7번). 먼저 막아야 한다.

## 2. 재현

모의 모델이 의미 분석에서 `array_to_struct`와 대상명을 그대로 내도록 하고 실행했다. 모두 종료 코드 1(검토 필요)로 끝났다.

## 3. 지금 변환기와 요청의 차이

| | 지금 변환기 | 요청 1: 전문 버퍼 | 요청 2: 병렬 배열 |
|---|---|---|---|
| 대상 | 이름이 정확한 배열 하나 | 버퍼(배열, 포인터, 함수 인자)의 위치 접근 | 같은 레코드 번호로 쓰는 배열 여러 개 |
| 필드가 되는 것 | 요소(1차원) 또는 열(2차원) | 바이트 구간(위치, 길이) | 배열 하나가 필드 하나 |
| 인덱스의 뜻 | 필드 번호 | 바이트 위치 | 레코드 번호 |
| 필요한 분석 | 상수 인덱스 | 숫자 인덱스, 포인터 위치, 커서 증가, 읽기·쓰기 길이 | 함께 쓰이는 정도, 사용처 분류 |
| 결과 | 새 구조체 하나 | 기존 구조체에 대응하거나 새 구조체 | 구조체의 배열 하나 |

## 4. 검토사항별 판단

시제품은 검토용 스크립트이고 `vupdate.py`에는 들어 있지 않다. 탐지는 sLLM을 쓰지 않는다.

### 4.1 전문 처리 대상 탐지: 가능(읽는 꼴에 한해)

함수의 문장을 순서대로 따라가며 커서 변수의 값을 계산하고, 버퍼 접근마다 (위치, 길이, 상대편)을 뽑는다. 분기와 반복은 보수적으로 다룬다.

| 읽는 것 | 예 |
|---|---|
| 숫자 인덱스 | `&pBuff[5]`, `pBuff[27] = 0x03` |
| 포인터 위치 | `pBuff + 11` |
| 커서 증가 | `n = 0; … n += 6;`, `n += sizeof(h->lot);`, `buf[n++]` |
| 길이 | `memcpy`·`strncpy`·`memset`의 길이 인자, `sprintf` 형식의 폭(`%06d` → 6), 요소 쓰기는 1 |
| 반복 안 | 한 바퀴 안의 상대 위치(+0, +10, +20) |
| 분기 뒤 | 갈래마다 값이 같으면 유지, 다르면 "모름"과 그 `if`의 줄 번호 |

합성 예제(함수 5개, 문장 26개)의 결과:

| 상태 | 문장 수 |
|---|---|
| 확정 | 18 |
| 확정(반복 안의 상대 위치) | 4 |
| 버퍼 전체(`memset(buf, ' ', sizeof(buf))` 등) | 2 |
| 위치 모름(분기에 따라 커서 값이 다름) | 2 |

- `pBuff`, `szSend`(커서 `nIndexCount`), 받은 전문 `pRecv` 모두 필드 표가 나왔다. 예: `tc[0..5), seq[5..11), lot[11..21), qty[21..27), f27[27..28)`.
- 기존 구조체와의 대응도 나왔다. 예: "기존 구조체 MES_HDR 와 배치가 맞음: 멤버 4개 가운데 4개가 위치와 길이까지 같음".
- 공개 코드(Notepad++ 804개 파일, 함수 12,548개)에서는 함수 7개, 문장 35개만 잡혔다(5.5초). 전문을 다루지 않는 코드에서 잘못 잡는 양은 적었다.

시제품이 **읽지 못한 꼴**(따로 돌려 확인함):

| 꼴 | 결과 | 넣을 수 있는가 |
|---|---|---|
| 포인터를 커서로 씀(`p = out; … p += 5;`) | 탐지 안 됨 | 같은 방법으로 가능(구현 항목) |
| 위치를 올리는 일을 보조 함수가 함(`PutField(buf, &pos, v, 5)`) | 탐지 안 됨 | 보조 함수의 인자 역할을 설정에 적으면 가능 |
| 길이가 실행 중에 정해짐(`strlen(name)`) | "길이 모름", 그 뒤는 "위치 모름" | 불가. 사유와 줄을 남긴다 |
| 분기에 따라 배치가 달라짐 | 그 뒤는 "위치 모름" | 갈래별 표로 나누는 것은 가능(구현 항목) |

실제 코드가 어느 꼴인지에 따라 확정 비율이 크게 달라진다. 8절의 확인이 필요한 이유다.

### 4.2 수정 요청 연결: 타당. 단, 일반 수정으로 넘기는 것은 권하지 않음

- **배열 선언 교체와 분리하는 것에 동의한다.** 도구가 필드 대응을 먼저 확정하고, 그 표를 모든 조각의 수정 요청에 같이 붙인다.
- **후보 실패 시 일반 수정 경로로 넘기는 것은 권하지 않는다.** 구조체 변환은 정의와 사용처가 여러 조각에 걸친다. 표 없이 조각만 보내면 모델이 조각마다 구조체를 따로 지어 서로 맞지 않는다. 넘기지 않은 것 자체보다, 위치와 사유 없이 끝난 것이 문제다(4.4).
- 전문 버퍼는 **겹쳐 보기** 방식을 권한다. 버퍼와 전송 호출은 그대로 두고, 버퍼의 처음을 구조체 포인터로 본다.

```c
BUILDBYINDEX_PBUFF_MSG* pMsg_pBuff = (BUILDBYINDEX_PBUFF_MSG*)pBuff;   /* 추가 */
memcpy(&pBuff[5], h->seq, 6);     →   memcpy(pMsg_pBuff->seq, h->seq, 6);
memcpy(pBuff + 11, h->lot, 10);   →   memcpy(pMsg_pBuff->lot, h->lot, 10);
```

| 겹쳐 보기의 성질 | 내용 |
|---|---|
| 문장 단위로 독립 | 일부만 바꿔도 컴파일되고 동작이 같다. 요청 전체를 되돌리는 장치가 필요 없다 |
| 확정 행은 규칙으로 됨 | 위치와 길이가 필드와 같으면 글자 치환이다. sLLM이 필요 없다 |
| 전송 바이트가 그대로 | 버퍼를 그대로 보내므로 전문이 바뀌지 않는다 |
| 기존 구조체 재사용 | 배치가 같으면 새로 만들지 않고 그 구조체로 본다(예제의 `pRecv` → `MES_HDR`) |

- 합성 예제에서 26문장 가운데 16문장을 규칙으로 바꿨고, gcc로 컴파일해 바꾸기 전과 출력이 같았다.
- **`sprintf`·`strcpy`로 쓰는 필드는 규칙으로 바꾸지 않는다.** 끝의 NUL이 다음 필드로 넘어간다. 멤버 접근으로 바꾸면 "필드를 넘겨 쓰는 코드"가 되고, 뒤에 보안 CRT 변환을 하면 문서 21의 결함이 다시 난다. 표에는 남기고 위치 접근 그대로 둔다(예제에서 1문장).
- sLLM에 맡길 것: 위치 모름인 문장, 필드 이름 짓기(`f27` 같은 임시 이름). 표 100행은 도구의 추정으로 약 2,200토큰이어서 요청 한도 안에 든다. 조각에 나오는 행만 붙이면 더 줄어든다.

### 4.3 병렬 배열 그룹 분석: 가능

첫 차원의 크기가 같고, 같은 함수에서 같은 번호 식(`[i]`)으로 함께 쓰이는 배열을 묶는다. 묶음은 "구조체의 배열"로 바꾼다.

```c
char g_szLot[MAX_REC][FLD_LEN];  … int g_nQty[MAX_REC];
→ typedef struct { char szLot[FLD_LEN]; … int nQty; } G_REC_T;   G_REC_T g_Rec[MAX_REC];

g_szLot[i]        →  g_Rec[i].szLot
g_szUnit[i][0]    →  g_Rec[i].szUnit[0]
g_nQty[0] = 0;    →  g_Rec[0].nQty = 0;
```

| 사용처 | 처리 |
|---|---|
| 첨자 접근(`이름[번호]…`) | 규칙. **번호가 변수여도 글자 치환으로 된다** |
| `sizeof(이름)` | 규칙. `(sizeof(묶음[0].필드) * (레코드 수))` |
| 묶음의 배열을 연달아 0으로 지우는 문장들 | 규칙. `memset(묶음, 0, sizeof(묶음))` 하나로 |
| 이름을 통째로 사용(함수 인자, 포인터 계산, 통째 복사) | sLLM 또는 수동. 위치와 문장을 남긴다 |
| 초기화 목록이 있는 선언 | 목록을 레코드 순서로 다시 짜야 한다(이번 시제품에 없음) |
| 통째로 파일·통신에 쓰는 곳 | 바꾸지 않는다. 저장·전송 배치가 달라진다 |

- 첫 번호는 항상 레코드 번호로 본다. 2절 7번(레코드 번호를 필드로 삼는 것)이 생기지 않는다.
- `[50][10]`, `[50][10][n]`은 첫 차원만 레코드 수로 쓰고 나머지 차원은 필드의 타입에 붙는다(`char szData[10][32];`). 차원 수에 따른 제한이 없다.
- 합성 예제: 배열 5개가 묶음 1개로 잡혔다. 첨자 접근 19곳과 0으로 지우는 문장 5곳을 규칙으로 바꿨고, gcc로 컴파일해 바꾸기 전과 출력이 같았다.
- 적재, 소비, 전송 변환도 함수별로 갈렸다. 예: `LoadRecords()` 쓰기 5, `SendRecords()` 읽기 7 가운데 전문 버퍼로 옮김 5.
- 공개 코드(Notepad++, 배열 선언 206개)에서는 묶음 0개, 약한 후보 쌍 3개였다(2.3초).
- 이 변환은 선언이 바뀌므로 **요청 단위로 전부 되거나 전부 되돌려야 한다.** 지금 있는 되돌리기 장치를 그대로 쓴다.

### 4.4 결과 집계: 가능. 가장 먼저 할 일

전문 처리 문장과 병렬 배열 묶음을 따로 집계하고, 미처리에도 위치를 남긴다.

| 구분 | 기준 | 탐지 | 수정 요청 | 실제 변환 | 미처리(사유, 위치) |
|---|---|---|---|---|---|
| 전문 처리 문장 | 패키지 전체의 문장 수 | 요청 대상에 든 수 | 규칙 n, sLLM n | 적용·검증된 수 | 위치 모름(분기) `Src/a.c:35` … |
| 병렬 배열 묶음 | 묶음 수, 배열 수, 사용처 수 | 요청 대상에 든 수 | 규칙 n, sLLM n | 적용·검증된 수 | 통째 사용 `Src/b.c:120` … |

- 이름이 코드에 있는데 배열이 아니면 "배열 MES"라고 쓰지 않고, 그 이름이 나온 파일과 줄, 무엇으로 쓰였는지를 적는다.
- 탐지 결과는 요청과 무관하게 `out/`에 표로 남긴다. 사람이 대상을 고를 때 쓴다.

### 4.5 전송용 구조 내부 배열: 동의. 묶어서 바꿀 수 없다

- 구조체의 배치가 곧 전문이다. 안에 있는 병렬 배열을 레코드로 묶으면 바이트 순서가 바뀐다(`lot[0..49], item[0..49]` → `lot[0], item[0], lot[1], …`). 받는 쪽도 같이 바꿔야 한다.
- 도구는 전송용으로 보이는 구조체를 찾아 **대상에서 빼고 사유를 남긴다.** 시제품의 기준: `#pragma pack` 안에서 정의됐거나, 입출력 함수의 인자에 `sizeof(그 타입)`이 나온다. 예제에서 `MES_SEND_T`와 그 안의 배열 4개가 빠졌다.
- 자체 전송 함수를 거치면 도구가 알 수 없다. 함수 이름을 설정에 적게 한다(지금의 `limits.scrt_raw_calls`와 같은 방식).
- 전송용 구조로 **옮겨 담는 쪽**(작업용 전역 배열)은 4.3의 대상이다.

### 4.6 대상명 문제(일반 명칭)

- 의미 분석 모델은 코드를 볼 수 없으므로 이름을 맞힐 수 없다. 대상은 **도구가 코드에서 찾은 후보**에서 골라야 한다.
- 방법 1(권장): 탐지 결과 표를 먼저 내고, 사람이 버퍼나 묶음을 골라 요청 파일에 적는다. 구조체와 필드의 이름도 이때 정한다.
- 방법 2: 후보에 번호를 붙여 모델에 "해당하는 번호만" 묻는다(지금 낱말로 함수 이름을 고르는 호출과 같다). 모의 모델로만 확인된 방식이라 실제 모델의 정확도는 모른다.

## 5. 제안하는 처리 흐름

```
구조 탐지(sLLM 없음)
 ├ 전문 버퍼 표: 함수·버퍼별 (줄, 읽기/쓰기, 위치, 길이, 상대편, 상태, 사유)
 ├ 병렬 배열 묶음: 배열, 레코드 수, 사용처 분류, 막는 곳
 └ 전송용 구조체와 그 안의 배열(대상에서 뺌)
요청 연결
 ├ 대상 정하기: 정확한 이름 → 그 버퍼·묶음 / 일반 낱말 → 후보에서 고름(4.6)
 ├ 병렬 묶음 → 구조체의 배열: 첨자·sizeof·0 지우기는 규칙, 통째 사용은 sLLM(묶음 정의를 붙임), 요청 단위로 되돌림
 └ 전문 버퍼 → 겹쳐 보기: 확정 행은 규칙, 위치 모름은 sLLM(필드 표를 붙임) 또는 그대로 둠
집계: 전문 문장과 병렬 묶음을 따로. 미처리에 사유와 위치
```

지금 변환기(열 상수 → 필드)는 남기되 두 가지를 막는다: 변수 인덱스가 있는 1차원 배열을 숫자 인덱스만 보고 필드로 쪼개는 것, 문자열 배열(`char [N][L]`)을 글자 단위 필드로 쪼개는 것.

## 6. 확인한 것과 확인하지 못한 것

| 무엇 | 조건 | 결과 |
|---|---|---|
| 실패 재현 8건 | 0.9.3, 합성 예제, 모의 모델 | 모두 재현(2절) |
| 전문 필드 탐지 | 시제품, 합성 예제 26문장 | 확정 22(상대 위치 4 포함), 버퍼 전체 2, 위치 모름 2 |
| 겹쳐 보기 변환 | 시제품, gcc 13 | 16문장 변환, 바꾸기 전과 출력 같음 |
| 병렬 묶음 탐지와 변환 | 시제품, gcc 13 | 5개 배열 1묶음, 24곳 변환, 바꾸기 전과 출력 같음 |
| 잘못 잡는 양 | 시제품, Notepad++ | 전문 문장 35개(함수 7개), 병렬 묶음 0개 |

확인하지 못한 것:

- 실제 코드. 합성 예제는 설명을 듣고 만든 것이라 접근 꼴이 다를 수 있다(4.1의 읽지 못한 꼴).
- cl에서의 컴파일. gcc로만 봤다.
- 통째 사용처와 위치 모름 문장을 실제 gemma4가 표를 받아 바르게 고치는지.
- 같은 이름의 다른 기호(지역 변수, 다른 구조체의 멤버), 매크로로 감싼 접근, 클래스 멤버 배열의 변환. 시제품은 파일 범위 배열만 바꿨다.

## 7. 진행 순서 제안

| 단계 | 내용 | 위험 |
|---|---|---|
| 1 | 탐지와 집계만 넣는다(코드를 고치지 않음). 미처리에 위치와 사유. 지금 변환기의 잘못된 변환 두 가지를 막는다 | 낮음 |
| 2 | 병렬 배열 묶음 → 구조체의 배열 | 중간(선언이 바뀜. 요청 단위 되돌리기) |
| 3 | 전문 버퍼 → 겹쳐 보기 | 낮음~중간(문장 단위. 전송 바이트는 그대로) |

1단계를 실제 코드에 돌린 탐지 결과를 보고 2, 3단계의 범위를 정하는 순서를 권한다.

## 8. 정해 주실 것

1. 전문 버퍼의 결과 꼴: **겹쳐 보기**(버퍼를 두고 구조체 포인터로 봄, 권장)인가, 버퍼를 구조체 변수로 **교체**하는 것인가. 교체는 선언과 전송 호출까지 한 번에 바뀌어야 한다.
2. 1단계만 먼저 넣을지, 1~3단계를 한 번에 넣을지.
3. 실제 코드의 꼴: 포인터 커서나 보조 함수로 조립하는지, 병렬 배열이 전역인지 클래스 멤버인지, 초기화 목록이 있는지. 시제품을 실제 코드에 돌린 요약(상태별 수, 사유별 수)만 알려 주셔도 된다.

시제품 실행(읽기만 한다. sLLM을 쓰지 않는다):

```
python proto_msg.py <vupdate.py 가 있는 폴더> <패키지 폴더> --quiet
python proto_par.py <vupdate.py 가 있는 폴더> <패키지 폴더> --quiet
```
