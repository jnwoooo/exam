## 1. 두 질문에 대한 답

**배열 선언을 구조체로 바꾸는 일은 LLM에 맡길 수 있는 과제가 아닌가.** 맡길 수 있다. 다만 대부분은 LLM이 필요 없었다. 0.5.0에서 "필드의 타입을 알아야 한다"고 적은 것은 틀린 판단이었다. 배열에서 온 필드의 타입은 배열의 요소 타입 그대로이고, 필드의 순서는 인덱스 값으로 정해진다. 둘 다 패키지에서 읽을 수 있다. 그래서 0.6.0은 선언 교체와 구조체 정의 생성을 규칙으로 하고, 규칙으로 정할 수 없는 사용처(배열 이름을 통째로 넘기는 곳, 변수 인덱스)만 sLLM에 맡긴다. sLLM에는 새 구조체 정의를 지침에 넣어 보낸다(2절).

**DB·HMI 도구 규칙은 일반적인 제품 기본값으로 정리할 수 있지 않은가.** 정리했다. 제품 이름을 받지 않아도, 코드가 쓰는 헤더·클래스·연결 문자열을 보면 어떤 DB 접근 기술과 HMI 구성 요소를 쓰는지 알 수 있다. 그것으로 켜지는 기본 규칙 27개와, 환경값 축에 적은 제품 이름으로 고르는 확인 목록을 넣었다(3절). 제품의 판마다 다른 세부(특정 판에서 바뀐 함수 이름 등)는 여전히 없다. 그것은 실제 제품과 판을 알아야 한다.

## 2. 배열 → 구조체: 선언 교체

요청 유형 `array_to_struct`가 이제 선언까지 바꾼다.

```cpp
// 전                                          // 후
enum { IDX_A, IDX_B = 2, IDX_C };              enum { IDX_A, IDX_B = 2, IDX_C };
#define TBL_SIZE 4                             #define TBL_SIZE 4
static unsigned int g_tbl[TBL_SIZE] = {0};     typedef struct TBL_T
                                               {
                                                   unsigned int a;
                                                   unsigned int reserved_1;
                                                   unsigned int b;
                                                   unsigned int c;
                                               } TBL_T;
                                               static TBL_T g_tbl = {0};
memset(g_tbl, 0, sizeof(g_tbl));               memset(&g_tbl, 0, sizeof(g_tbl));
g_tbl[IDX_C] = g_tbl[IDX_B] + 1;               g_tbl.c = g_tbl.b + 1;
Send(g_tbl);                                   Send(g_tbl);        <- sLLM 또는 수동 검토
g_tbl[i] = 0;                                  g_tbl[i] = 0;       <- 수동 검토(요청에서 켜면 sLLM)
```

| 대상 | 처리 | 누가 |
|---|---|---|
| 요소 타입, 배열 크기 | 선언에서 읽는다. 크기가 이름이면 `#define`이나 `enum`에서 값을 찾는다 | 규칙 |
| 필드 순서 | 매핑의 인덱스 이름을 `#define`이나 `enum`에서 찾아 값 순서로 놓는다 | 규칙 |
| 매핑에 없는 인덱스 | `reserved_번호`로 채워 크기와 배치를 배열과 같게 둔다 | 규칙 |
| 구조체 정의 | 첫 선언 앞에 한 번 넣는다. 헤더에 `extern` 선언이 있으면 그 헤더에 넣는다 | 규칙 |
| 선언 | `타입 이름[크기]` → `구조체 이름`. `extern`, `static`, 초기값은 그대로 둔다 | 규칙 |
| 상수 인덱스 접근 | 필드 접근으로(0.1.0부터) | 규칙 |
| `memset`, `memcpy`, `fwrite`, `send` 등의 인자 | `&`를 붙인다 | 규칙 |
| `sizeof(이름)` | 그대로 둔다 | |
| 배열 이름을 통째로 쓰는 그 밖의 곳(함수 인자, 포인터 연산) | sLLM(기본) 또는 수동 검토. 지침에 새 정의를 넣는다 | sLLM |
| 변수 인덱스 접근(`g[i]`) | 수동 검토(기본) 또는 sLLM | sLLM |

모든 수정은 검토 대상으로 표시한다. 계약(새 정의와 처리 건수)은 `report.md`의 "변경 계약"에 나온다.

요청에 더 적을 수 있는 값:

| 값 | 뜻 | 기본 |
|---|---|---|
| `struct_name` | 구조체 이름 | 배열 이름을 대문자로 바꾸고 `_T`를 붙인 것 |
| `types` | 필드별 타입. `{"필드": "타입"}`. 주면 배열과 크기·배치가 달라질 수 있다 | 요소 타입 |
| `unmapped` | 매핑에 없는 인덱스. `reserved`(채운다) 또는 `drop`(뺀다. 크기가 달라진다) | reserved |
| `convert_declaration` | 거짓이면 선언을 바꾸지 않고 수동 검토로 남긴다(0.5.0의 동작) | 참 |
| `llm_other_uses` | 배열 이름을 통째로 쓰는 곳을 sLLM에 맡긴다. 거짓이면 수동 검토 | 참 |
| `llm_variable_index` | 변수 인덱스 접근을 sLLM에 맡긴다 | 거짓 |

**바꾸지 못하고 수동 검토로 남기는 경우**(이유가 수동 검토 목록에 적힌다): 인덱스 이름의 값을 패키지에서 찾지 못함(계산식으로 준 값 포함), 배열 크기를 정할 수 없음, 선언마다 요소 타입이 다름, 인덱스가 겹치거나 크기를 벗어남.

**알아 둘 것**
- 변수 인덱스 접근이 남아 있으면 그 줄은 컴파일되지 않는다(구조체에는 `[]`가 없다). 그 줄을 필드별로 풀어 쓰는 것이 이 요청의 남은 일이다.
- 선언이 여러 `.cpp`에 있고 헤더에는 없으면, 정의를 넣은 파일 말고는 구조체를 모른다. 변경 계약에 "정의를 공용 헤더로 옮겨야 한다"고 나온다.
- 다차원 배열과 구조체 배열은 다루지 않는다.

## 3. DB·HMI 기본 규칙

### 3.1 코드가 쓰는 것으로 켜지는 규칙(27개)

탐지는 세 군데를 본다. `#include`와 `#import`의 파일 이름, 문자열 리터럴(연결 문자열), 본문의 클래스·함수 이름이다. 파일마다 한 줄로 묶어 낸다.

- **T0**는 코드가 아니라 설치와 설정으로 맞추는 것이다. `project_settings.md` 2절에 `[DB]`, `[HMI]`로 나온다.

### 3.3 제품이 정해지면 더하는 방법

- 확인 목록은 M05의 `PRODUCT_NOTES`에 `(축, 낱말, 항목)` 한 줄을 더한다.
- 규칙은 `config/rules.json`에 더한다. 코드 수정이 필요 없다.

```json
{ "id": "R-T3-HMI-MYTOOL-API", "tier": "T3", "category": "HMI", "collapse": true, "detector": "tech",
  "title": "[HMI] 우리 HMI 도구의 구 API 사용. 새 판에서는 TagReadEx 로 바꾼다",
  "include": "(?i)^mytool\\.h$", "code": "\\bTagRead\\s*\\(", "strings": "(?i)mytool\\.dll",
  "when": { "axis_changed": ["hmi"] },
  "tests": [ { "code": "#include \"mytool.h\"\nvoid f() { TagRead(1); }", "hits": 2 } ] }
```

고치는 방법이 하나로 정해지면 `"detector": "tech"` 대신 `pattern`과 `action`으로 자동 치환 규칙(T1)을 만든다(`04_개발구조.md` 10절).

## 4. 한계와 근거

- **제품별 판 세부는 없다.** 3.1은 "이 기술을 쓰고 있다"와 "전환할 때 널리 알려진 주의점"까지다. 특정 제품의 특정 판에서 바뀐 함수 이름 같은 것은 넣지 않았다.
- **헤더 이름으로 추정한다.** `dtl.h`, `sqlcli.h`처럼 흔한 이름은 다른 것일 수 있다. 맞지 않으면 `--disable-rule`로 끈다.
- **실제 Pro*C 파일로 확인하지 못했다.** `.pc`를 C 소스처럼 읽으므로 SQL 문장 안의 따옴표가 특이하면 그 줄의 탐지가 빠질 수 있다. 수정이 틀리면 그 파일을 `--exclude`로 뺀다.
- **근거.** 이번에 문서로 다시 확인한 것은 세 가지다: OO4O의 지원 종료(Oracle 문서), SQL Server Native Client의 제거와 새 드라이버의 암호화 기본값(Microsoft 문서), DCOM 보안 강화 KB5004442(Microsoft 문서). 나머지 항목은 널리 알려진 내용을 적은 것이고 이번에 다시 확인하지 않았다. 적용 전에 제조사 문서를 본다.
- 확인은 리눅스의 합성 예제로만 했다(`tests/test_v060.py` 12항목).
