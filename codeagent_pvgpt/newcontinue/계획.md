# newcontinue — Continue 호환 CLI 하네스 계획서

> **무엇**: Continue 공식 CLI(`cn`)의 하네스 동작을 **소스 기준으로 최대한 똑같이** 다시 만들고, 사내에 필요한 기능(중앙 정책·인코딩 보존·백업·감사·반복 상한 등)만 **덧붙인** CLI. 명령 이름은 `ncn`(가칭).
> **왜**: ① Continue IDE 확장이 예상대로 동작하지 않는 경우가 있음 ② **Visual Studio(VS Code 아님)·Windows 7** 같은 구식 환경은 Continue 확장도 cn도 못 씀 ③ Continue로는 못 하는 통제가 필요함.
> **기준 소스**: github.com/continuedev/continue, 커밋 `5522c6f`(2026-07-20), `extensions/cli/src` + `core/edit`·`core/util`·`core/llm` 일부. 분석 요약: 부록 A.
> **개정**: 1차(10-10) → **2차(10-10)**: Windows 7 추가, 언어 재검토(2장), 압축 상세(5-5), 시스템 메시지 cn과 동일, 토큰 세기 cn과 동일, 화면 수준 확정, 배포·실행 방법(8·9장) 추가. 남은 결정은 11장. **3차(10-10)**: 진행 방식 확정 — Python 3.14로 macOS에서 먼저, Windows는 나중에 결정(12장). **4차(10-29)**: VS 2022 확장 + `ncn --stdio` 구조 확정, 검토 결과(14장). **Windows 7 제외·ACP·WPF 확정(14-5)** — 아래 1~12장의 Windows 7 관련 내용은 14-5가 우선.

## 0. 요약
- **어렵지 않다.** cn의 하네스 핵심(루프·도구·권한·대화 압축·시스템 메시지·설정 로딩)은 TypeScript 약 8~9천 줄이다. 화면(TUI)은 따로 단순하게 만든다.
- **Windows 7이 들어오면서 cn(Node 18 필요)은 실행 자체가 불가** → 직접 만드는 것이 필수가 됐다(2장).
- **언어는 범용성 기준으로 재검토**: 1차 계획의 Python은 "서버와 같은 언어·1판 코드 재사용" 때문이었지 범용성 때문이 아니었다. Windows 7까지 단일 실행 파일로 가장 넓게 덮는 것은 Go(1.20 도구 체인). **진행 결정: 우선 Python 3.14로 macOS에서 만들고 시험, Windows용은 그 뒤에 Python 3.8 빌드 / Go 이식 중 결정**(12장).
- **설정은 Continue 것을 그대로 읽는다**: `~/.continue/config.yaml`, `permissions.yaml`, `.continue/rules/`, `AGENTS.md`, skills(4장).
- **정확도**: LLM에 보내는 요청 본문(시스템 메시지·도구 정의·대화 형식)과 도구 결과 문자열을 **cn과 같게**. 같은 가짜 LLM 앞에서 cn과 ncn을 돌려 비교하는 **차등 테스트**로 측정(10장).

## 1. 사용 환경 — 클라이언트 사양을 모르므로 "가장 넓게"

| 항목 | 대상 |
|---|---|
| OS | **Windows 7 SP1 / 8.1 / 10 / 11** (32비트·64비트 모두), macOS, Linux. Windows가 우선 |
| IDE | 상관없음 — Visual Studio(2010~2022), IntelliJ, VS Code, 메모장. **터미널 프로그램**이라 IDE와 독립 |
| 네트워크 | 폐쇄망. 인터넷 접속 없음 — cn이 하는 시작 시 버전 확인·기본 설정 내려받기도 하지 않음 |
| 설치 권한 | **관리자 권한 없이** 사용자 폴더에 복사만으로 동작 |
| 런타임 | **PC에 아무것도 설치하지 않아도 되게**(Node·Python·.NET 설치 요구 없음) |
| 서버 | 기존 코드에이전트 서버(:8200 `/v1` LLM 프록시, `/mcp` 도구) 그대로 |
| 레거시 소스 | CP949·CRLF·BOM 섞인 저장소 → 인코딩·줄바꿈 보존 필수(6장 E3) |
| 콘솔 | Windows 7 콘솔(conhost)은 ANSI 색 코드를 모름, 기본 코드 페이지 949 → 화면 출력은 Win32 콘솔 API로(3장) |

```
                                                          ├─ /v1 ──▶ 코드에이전트 서버 :8200 ──▶ LLM(gemma4 등, 바뀔 수 있음)
  (Continue 확장 사용자도 같은 설정)                         └─ /mcp ─▶   search_code · search_docs · request_fix
  PC 안의 파일 읽기·수정·명령 실행은 ncn이 직접(권한 확인 후)
```

## 2. 구현 언어 — 범용성 검토

### 2-1. 질문: "Node처럼 OS 버전이 낮으면 실행 자체가 안 되는 경우가 있나?" → **있다**
런타임(언어 실행 환경)마다 지원하는 마지막 Windows가 정해져 있고, 그보다 새 버전은 **설치 프로그램이 거부하거나, 실행 시 필요한 Windows 기능이 없어 바로 종료**된다.

| 런타임 | Windows 7을 지원하는 마지막 버전 | 그 이후 | cn·라이브러리 요구 | Windows 7에서 |
|---|---|---|---|---|
| **Node.js** | 12.x / 13.x | 14부터 공식 미지원, 18+는 Windows 8.1+ API 필요 | **cn은 Node 18 대상** | **실행 불가** |
| **Python** | **3.8**(2024-10 지원 종료) | 3.9부터 Windows 7 미지원 | MCP 공식 SDK `mcp`는 **3.10+** | 3.8로만 가능 → MCP 클라이언트 직접 구현, 라이브러리를 옛 버전에 고정 |
| **Go** | **1.20** | 1.21부터 Windows 7·8 미지원 | MCP 공식 Go SDK는 1.25+ | 1.20으로 빌드하면 가능 → MCP 클라이언트 직접 구현, 라이브러리를 1.20 호환 버전에 고정 |
| **.NET Framework 4.8**(C#) | 4.8(Windows 7 SP1 지원) | — (OS와 함께 지원 유지) | — | Windows 7은 **4.8 설치 필요**(오프라인 설치 파일 약 120MB), Windows 10 1903+·11은 기본 포함 |
| (참고) ripgrep(rg.exe) | Rust 1.77 이하로 빌드한 판 | Rust 1.78부터 Windows 10+ | cn의 Search 도구 | 옛 rg 동봉 또는 **검색 기능 내장**(5-3) |

Windows 7에서 위 표의 "마지막 버전"도 **SP1 + 일부 업데이트**(예: KB2533623, Python은 UCRT KB2999226)가 필요할 수 있다 → P0에서 깨끗한 Windows 7 SP1 VM으로 확인.

### 2-3. 추천과 이유
- **추천: Go(1.20 도구 체인으로 빌드, 의존 라이브러리 버전 고정)**
  - Windows 7 x86/x64 ~ 11, macOS, Linux를 **파일 하나**로 덮는 유일한 선택지. 설치·런타임 요구가 없고 백신 오탐이 적다.
  - 단점: 팀에 새 언어, 최신 Go 라이브러리 일부를 못 씀(MCP·토크나이저는 직접 또는 옛 버전) → 필요한 외부 라이브러리가 적은 구조(표준 라이브러리 위주)로 설계.
  - 같은 코드를 최신 Go로도 빌드할 수 있게 유지 → Windows 7이 사라지면 도구 체인만 올림.
- **차선: C#(.NET Framework 4.8)** — 대상이 Windows뿐이고 Visual Studio 확장(VSIX)까지 갈 계획이 확실하면.
- **진행 결정(3차)**: 1단계는 Python 3.14 + macOS. Windows 단계에서 다시 고르되, 어느 쪽이든 문제가 없도록 12-2의 규칙을 지키며 만든다.
- **Python을 1순위에서 내렸던 이유**: Windows 7에서는 지원 종료된 3.8에 묶이고, MCP 공식 SDK를 못 쓰며, 실행 파일 묶음이 크고 백신 오탐이 잦다. 서버 쪽(코드에이전트·RAG)은 지금처럼 Python 유지 — 클라이언트만 다른 언어여도 HTTP로만 대화하므로 문제없음.

## 3. 화면 수준(확정: 추천안)
- **1차는 단순한 대화형**: 입력 줄 → 응답 스트리밍 출력 → 도구 호출 표시(도구·핵심 인자·결과 요약) → 승인 질문(3가지) → 현재 모드 표시. cn의 Ink(React) 화면 모양은 맞추지 않는다.
- **Windows 7 대응**: 색은 Win32 콘솔 API로(ANSI 미지원 콘솔), 한글은 유니코드 출력 API(WriteConsoleW)로 — 코드 페이지 949 콘솔에서도 깨지지 않게. Windows 10+ 와 macOS/Linux는 ANSI 사용.
- **화면 없는 모드**도 처음부터: 헤드리스(`-p`)와 stdio(JSON 줄, IDE 연동용).

## 4. 설정 — Continue 설정을 그대로 사용

### 4-1. 읽는 파일(cn과 같은 위치·우선순위)
| 파일 | 내용 | 비고 |
|---|---|---|
| `--config <경로>` → 없으면 `$CONTINUE_GLOBAL_DIR/config.yaml`(기본 `~/.continue/config.yaml`, Windows는 `%USERPROFILE%\.continue\config.yaml`) | 모델·MCP·규칙 | cn은 둘 다 없으면 인터넷에서 기본 설정을 받음 → **ncn은 안내 후 종료** |
| `~/.continue/permissions.yaml` | `allow`/`ask`/`exclude` 목록 | "다시 묻지 않기"도 여기 기록 |
| 작업 폴더의 `AGENTS.md` → `AGENT.md` → `CLAUDE.md` → `CODEX.md` 중 첫 번째 | 프로젝트 지침 | 작업 폴더만(상위 폴더는 안 찾음 — cn과 같음) |
| `./.continue/rules/**.md`, `~/.continue/rules/**.md` | 항상 적용 규칙 | `alwaysApply: true` 또는 globs가 없는 규칙 |
| `.continue/skills/*/SKILL.md`, `.claude/skills/*/SKILL.md`, `~/.continue/skills/*/SKILL.md` | 스킬 | |
| `~/.continue/.env`, 작업 폴더 `.continue/.env`, 환경변수 | `${{ secrets.X }}` 값 | 정확한 순서는 P0에서 원본 확인(7장) |
| **[추가]** 관리자 정책 파일 | 사용자가 못 바꾸는 권한·한도 | Windows `%ProgramData%\ncn\policy.yaml`, 그 밖 `/etc/ncn/policy.yaml` |

### 4-2. config.yaml에서 쓰는 키
```yaml
models:                       # 역할이 chat이거나 역할이 없는 첫 모델 = 대화 모델(cn과 같음), 역할 subagent = 하위 에이전트
  - provider: openai          # OpenAI 호환만(사내 구성). 다른 provider는 안내 후 종료
    model / apiBase / apiKey
    roles / capabilities
    defaultCompletionOptions: { contextLength, maxTokens, temperature, topP, ... }   # ★ contextLength·maxTokens는 압축 시점을 정함(5-5)
    requestOptions: { timeout, headers, verifySsl }
    chatOptions: { toolOverrides, baseSystemMessage }
mcpServers:                   # command(stdio) / type: sse | streamable-http, url, requestOptions.headers, apiKey, env, cwd
rules:                        # 문자열 또는 {name, rule}
```
지원 안 함: Hub의 `uses:` 블록, Continue 로그인. 모르는 키는 무시하고 경고만.

## 5. 하네스 구조 — cn과 같은 동작

### 5-1. 에이전트 루프(cn `streamChatResponse.ts` 순서 그대로)
```
사용자 메시지
 └▶ 반복:
     1. 시스템 메시지 만들기(모드 반영)                         ← 5-4
     2. 도구 목록 만들기(exclude 도구 제외, 헤드리스는 ask 도구도 제외, toolOverrides 적용)
     3. 압축 검사 ①(호출 전)                                    ← 5-5
     4. 토큰 한도 검사 — 넘으면 끝에서부터 잘라 맞춤, 그래도 넘으면 오류
     5. LLM 스트리밍 호출 {model, messages, stream, tools, max_tokens, temperature, top_p, ...}
        - 재시도: 최대 10회, 1초부터 ×1.6, 최대 30초, 지터 50~100% (429/502/503/504·연결 오류만)
        - 도구 호출 조각 모으기: id 기준, index→id 대응, arguments 문자열 이어 붙이며 매번 JSON 해석 시도
     6. 도구 호출이 없으면 → 턴 끝
     7. 도구 호출 처리                                          ← 5-2
     8. 압축 검사 ②(도구 결과로 한도 초과 시 강제) · ③(도구를 썼으면 일반)
     9. 이번 턴에 압축이 있었고 모델이 멈추려 하면 "continue"를 붙여 한 번 더
```
- 도구 결과는 assistant 메시지의 도구 호출 상태에 붙여 두고, LLM에 보낼 때 `role: "tool"`로 펼친다. 결과 없는 호출은 `Tool cancelled`.
- **[추가] 반복 상한**: cn에는 없다. ncn은 기본 50회 + 같은 도구·같은 인자 3회 연속 실패 시 멈추고 묻기(설정으로 끄면 cn과 동일).

### 5-2. 도구 호출 처리
| 단계 | 동작 | 모델에게 돌아가는 글(cn 원문) |
|---|---|---|
| 도구 찾기 | 없는 이름 | `Tool {name} not found` |
| 필수 인자 | 최상위 required만 | `Required parameter "{p}" missing for tool "{name}"` |
| 사전 처리 | Edit의 "먼저 읽었나"·"한 곳만 찾히나" 등 | 각 도구의 오류 글 |
| 권한 | **순서대로** 확인, 허락된 것은 바로 시작 → 실행은 **동시에**, 결과는 원래 순서 | 정책 거부 `Command blocked by security policy` / 사용자 거부 `Permission denied by user` |
| 실행 | 동시에 N개면 Read·Bash 출력 한도를 N으로 나눔 | 실패 `Error executing tool {name}: {메시지}` |
| 헤드리스 | 거부가 하나라도 있으면 턴 종료 | — |

### 5-3. 도구 구성(cn과 같은 이름·인자·설명·결과 글)
| 도구 | 인자(*필수) | 기본 권한 | 동작 요점 |
|---|---|---|---|
| **Read** | filepath* | allow | 앞의 `./` 제거, 민감 파일 차단. 10만 자/5천 줄 초과면 **잘라 주지 않고 오류**. 결과 `Content of {path}:\n{내용}`(줄 번호 없음). 읽은 파일 기억(Edit 조건) |
| **Write** | filepath*, content* | ask | 상위 폴더 생성. 기존 파일 `Successfully wrote to file: X\nDiff:\n…`, 새 파일 `Successfully created file: X` |
| **Edit** | file_path*, old_string*, new_string*, replace_all | ask | 이번 대화에서 Read한 파일만. 찾기: 정확히 → 앞뒤 공백 무시 → 대소문자 무시 → 공백 전부 무시(들여쓰기 보정). 없음/여러 곳은 cn 오류 글 |
| **MultiEdit** | file_path*, edits*[…] | ask | 차례로, 전부 되거나 전부 안 되게. 모델 이름이 gemini·claude·gpt·qwen·llama·mistral 등이면 Edit 대신 제공(cn 규칙) — **gemma는 Edit** |
| **Bash** | command*, timeout(초, ≤600) | ask | Windows `powershell.exe -NoLogo -ExecutionPolicy Bypass -Command`(**Windows 7 기본은 PowerShell 2.0** — 11장 Q5), 그 밖 `$SHELL -l -c`. 출력이 없는 시간 기준 180초. 출력은 뒷부분 남기고 5만 자/1천 줄 |
| **Search** | pattern*, path, file_pattern | allow | cn은 `rg` 실행. ncn은 **rg.exe가 있으면 cn과 같은 명령, 없으면 내장 검색이 rg와 같은 출력 형식**(`경로:줄:내용`, .gitignore 제외, 최대 100개). Windows 7에서 새 rg가 안 도는 문제 해결 |
| **List** | dirpath* | allow | 한 단계. `이름 (directory)` / `이름 (file, N bytes)` |
| **Fetch** | url* | allow | HTML→마크다운, 2만 자. 폐쇄망이므로 관리자 정책으로 exclude 권장 |
| **Checklist** | checklist* | allow | `Task list status:\n…` |
| **AskQuestion** | question*, options*, defaultAnswer | allow | 사용자 선택을 글로 |
| **CheckBackgroundJob** | job_id* | allow | Ctrl+B로 보낸 명령(최대 5개, 각 1천 줄) |
| **Skills** | skill_name* | allow | SKILL.md + 부속 파일 목록 |
| **Exit** | — | allow | 헤드리스에서만 |
| Subagent | description*, prompt*, subagent_name* | — | cn에서 베타 → 2차 |
| MCP 도구 | 서버가 준 이름 | ask(`*`) | 결과는 `content`를 JSON 문자열로 |

모드(cn과 같음): **plan** = Edit·MultiEdit·Write 숨김(Bash·MCP 허용) / **auto** = 전부 허용. `Shift+Tab`으로 순환.

### 5-4. 시스템 메시지(확정: **cn과 동일**)
cn `systemMessage.ts`의 글·순서를 **바꾸지 않고** 그대로 쓴다("Continue CLI"라는 이름, 커밋 서명 지시 포함).
```
You are an agent in the Continue CLI. Given the user's prompt, you should use the tools available to you to answer the user's question.
Notes:
1. IMPORTANT: You should be concise, direct, and to the point, since your responses will be displayed on a command line interface.
2. When relevant, share file names and code snippets relevant to the query
<env> Working directory / Is directory a git repo / Platform / Today's date </env>
<context name="gitStatus"> 대화 시작 시점 스냅샷 안내 + git status --porcelain </context>
[plan 모드] <context name="planMode"> …   [그 밖] <context name="commitSignature"> …
[헤드리스] 최종 답만 …                     [--format json] JSON만 …
<context name="userRules"> AGENTS.md 등 → --rule → config.yaml rules → .continue/rules </context>
```
- 커밋 서명은 cn과 같은 환경변수 `CONTINUE_CLI_DISABLE_COMMIT_SIGNATURE`로 끌 수 있다(cn과 같은 방법).
- Platform 값도 cn과 같게(Node의 `process.platform` 표기: `win32`/`darwin`/`linux`).
- **[추가] 사내 규칙**은 시스템 메시지를 고치지 않고 **관리자 정책의 규칙을 `userRules`에 넣는 방식**으로 — 시스템 메시지 본문은 cn과 바이트 단위로 같게 유지(차등 테스트 대상).

### 5-5. 대화 압축 — 구체적으로
대화가 길어지면 LLM의 입력 한도(컨텍스트)를 넘는다. cn은 **넘기 전에 지금까지의 대화를 LLM에게 요약시키고, 요약 하나로 대화를 갈아 끼운다.** ncn은 이 공식·글·순서를 그대로 쓴다.

**(1) 토큰 세기 — 확정: cn과 동일(모델이 바뀌어도 같은 규칙)**
- 글 → **o200k_base** 인코딩 토큰 수(cn이 쓰는 `gpt-tokenizer`의 기본 인코딩) × **모델 보정 배수**, 올림
  - 모델 이름에 `claude` 1.23 / `gemini` 1.18 / `stral`·`mixtral` 1.26 / **그 밖(gemma·qwen·llama 등) 1.0** (cn `core/llm/getAdjustedTokenCount.ts`)
- 여기에 cn `util/tokenizer.ts`의 고정 덧셈을 그대로: 메시지 구조, 도구 호출(이름 + 10 + 인자), 도구 정의(이름·설명·인자 필드), 시스템 메시지 등 — 값 전부 P0에서 옮김
- 실제 모델 토크나이저와는 다를 수 있다(cn도 같음). 실제 사용량은 서버 `/admin`이 따로 기록하므로 압축 시점 판단에만 쓴다.

**(2) 한도 계산(cn `compaction.ts` 공식)**
```
ctx       = contextLength (설정 없으면 200000)
maxTokens = maxTokens 설정값 (없으면 올림(min(ctx × 0.35, 64000)))
buffer    = min( max(maxTokens, 올림(0.2 × (ctx − maxTokens))), 15000 )
압축 기준  = ctx − maxTokens − buffer
입력 토큰(시스템 메시지 + 도구 정의 + 대화) ≥ 압축 기준  →  압축
```
| 예 | ctx | maxTokens | buffer | 압축 기준 | 비율 |
|---|---|---|---|---|---|
| A. gemma4-26b-32k, maxTokens 4096 설정(지금 config.yaml) | 32,768 | 4,096 | 5,735 | **22,937** | 70% |
| B. 같은 모델, maxTokens 미설정 | 32,768 | 11,469 | 11,469 | **9,830** | 30% — 너무 자주 압축 |
| C. 128k 모델, maxTokens 8192 | 131,072 | 8,192 | 15,000 | **107,880** | 82% |
| D. contextLength 미설정(모델이 실제 32k) | 200,000 가정 | 64,000 | 15,000 | 121,000 | **압축 전에 서버가 거절** |
→ 모델이 gemma4로 고정되지 않으므로 **모델마다 contextLength·maxTokens를 반드시 적는다.** ncn은 미설정이면 시작할 때 경고만 하고(동작은 cn과 같게) 넘어간다.

**(3) 언제 검사하나**
| 시점 | 종류 |
|---|---|
| 매 LLM 호출 직전(루프 3단계) | 일반 |
| 도구 결과를 붙인 뒤 한도를 넘었을 때 | 강제 |
| 도구를 쓴 뒤(루프 8단계) | 일반 |
| 헤드리스에서 사용자 메시지를 넣기 전 | 일반 |
| 사용자가 `/compact` 입력 | 수동 |

**(4) 압축 절차**
1. 화면에 `Approaching context limit (NK tokens). Auto-compacting chat history...`
2. 지금 대화 끝에 **요약 요청 사용자 메시지**를 붙인다(150토큰 예약). 원문 그대로:
   > Please provide a concise summary of our conversation so far, capturing the key context, decisions made, and current state. Format this as a single comprehensive message that preserves all important information needed to continue our work. You do not need to recap the system message, as this will remain. Make sure it is clear what the current stream of work was at the very end prior to compaction so that you can continue exactly where you left off without missing any information.
3. 그래도 한도를 넘으면 **끝에서부터 잘라 낸다**: 끝에서 두 번째가 사용자 메시지나 도구 호출이면 두 개를 한 쌍으로, 아니면 하나씩(안전 여유 100토큰)
4. 이 대화를 **평소와 같은 루프**로 LLM에 보내 요약을 받는다(도구 목록도 같이 감 — cn과 같음)
5. 대화를 `[시스템 메시지, assistant: 요약]` **두 개로 갈아 끼운다**. 나머지(도구 결과·파일 내용·마지막 사용자 메시지)는 버려진다
6. 화면에 `Chat history auto-compacted successfully.`
7. 작업 도중(도구 루프 중)이었으면 사용자 메시지 `continue`를 붙여 이어 간다

**(5) 압축 전후 예**
```
압축 전(약 23k 토큰)                          압축 후(약 1k 토큰)
system: (시스템 메시지)                        system: (시스템 메시지 — 그대로)
user: 쿠폰 할인 버그 고쳐줘                     assistant: [요약] 사용자는 쿠폰 할인 버그 수정을 요청.
assistant: → Search("apply_coupon")                      coupon/apply.py의 apply_coupon에서 반올림 누락 확인,
tool: (검색 결과 40줄)                                    Edit로 Decimal 적용 완료, 테스트 1개 실패(test_rate),
assistant: → Read coupon/apply.py                        다음 할 일: tests/test_coupon.py 기대값 확인…
tool: (파일 300줄)                             user: continue
assistant: → Edit …  tool: (diff)
assistant: → Bash pytest  tool: (출력 200줄)
```

**(6) 압축으로 잃는 것과 대응**
| 잃는 것 | 영향 | 대응 |
|---|---|---|
| 파일 내용·도구 결과 | 모델이 코드를 다시 봐야 함 | 요약 글이 "현재 작업"을 남기게 되어 있음 → 모델이 다시 Read |
| 마지막 사용자 메시지 원문 | 요약에 녹아 있음 | cn과 같게 유지 |
| "이번 대화에서 Read한 파일" 기록 | 압축 후에도 유지되는지 미확인 | P0에서 확인 후 cn과 같게 |

**(7) 실패하면**: 요약 호출이 실패하면 압축 없이 진행 → 호출 전 검사에서 끝부터 잘라 맞춤 → 그래도 넘으면 `Context length validation failed: …` 오류로 턴 종료.

**(8) ncn 추가(동작은 바꾸지 않음)**: 압축 전후 토큰 수를 감사 기록에 남기고, contextLength 미설정 경고.

### 5-6. MCP
- 설정의 `mcpServers`에 병렬 접속(stdio / sse / streamable-http). 도구 이름은 서버가 준 그대로.
- cn은 따로 시간 제한이 없음 → ncn은 `requestOptions.timeout`이 있으면 적용.
- 공식 SDK를 쓸 수 없는 언어 버전(2장)이므로 **최소 MCP 클라이언트를 직접 구현**: initialize · tools/list · tools/call, JSON-RPC over stdio / streamable-http / SSE. 지금 서버(`/mcp`, MCP SDK 2.x)로 시험.

## 7. 소스 추가 확인 — 결정이 아니라 **P0 작업**
1차 계획의 "Q4"는 사용자가 정할 것이 아니었다. **이번에 받은 소스에 빠져 있어 아직 못 본 부분**이 세 곳 있고, 그 내용이 ncn의 동작을 정하므로 구현 전에 받아서 읽고 그대로 옮긴다는 뜻이다.
| 빠진 소스 | 들어 있는 것 | 안 보면 생기는 차이 |
|---|---|---|
| `packages/terminal-security` | Bash 명령 중 **자동으로 막는 위험 명령 목록·판정 규칙** | cn은 막는 명령을 ncn이 실행하거나 그 반대 |
| `packages/config-yaml` | `${{ secrets.X }}` 해석 순서, `.env` 위치, config 검증 | 같은 config.yaml인데 키를 못 찾거나 다르게 읽음 |
| `core/indexing/ignore.ts` | Read·Edit가 거부하는 **민감 파일 목록** | 같은 파일을 cn은 거부, ncn은 읽음 |

## 8. 배포 방법
### 8-1. 결과물(Go 기준)
| 묶음 | 대상 | 내용 |
|---|---|---|
| `ncn-<버전>-windows-x64.zip` | Windows 7 SP1~11 64비트 | `ncn.exe`, `install.cmd`, `uninstall.cmd`, `config.template.yaml`, `README.txt` |
| `ncn-<버전>-windows-x86.zip` | Windows 7~10 32비트 | 같음 |
| `ncn-<버전>-macos-universal.tar.gz` | macOS(Intel·Apple) | `ncn`, `install.sh` |
| `ncn-<버전>-linux-x64.tar.gz` | Linux | `ncn`, `install.sh` |
- `ncn.exe` 안에 토큰 인코딩 파일(o200k)·내장 검색이 들어 있어 **파일 하나로 동작**. rg.exe는 선택(있으면 사용).
- 빌드는 인터넷이 되는 빌드 PC에서 한 번(Go는 한 PC에서 모든 OS용 교차 빌드) → 결과 zip만 폐쇄망으로 반입.
- **코드 서명: 당분간 없음**(결정). macOS 시험 단계는 소스 실행(`uv run`)이라 영향 없음. 실행 파일 배포 시 macOS는 Gatekeeper(처음 실행 시 "확인되지 않은 개발자" → 우클릭 열기 또는 `xattr -d com.apple.quarantine`), Windows는 SmartScreen·백신 경고 안내를 README에 넣는다.

### 8-2. 설치(관리자 권한 불필요)
`install.cmd`(Windows 7의 cmd에서도 동작하게 작성)가 하는 일:
1. `%LOCALAPPDATA%\ncn\`(Windows 7은 `C:\Users\<이름>\AppData\Local\ncn\`)에 `ncn.exe` 복사
2. 사용자 PATH에 추가(`setx` — Windows 7 포함 사용 가능)
3. `%USERPROFILE%\.continue\config.yaml`이 **없을 때만** 템플릿 복사(있으면 Continue 사용자의 설정을 그대로 씀)
4. 개인 토큰을 물어 `%USERPROFILE%\.continue\.env`에 `CODEAGENT_TOKEN=...` 기록
5. `ncn --doctor`로 점검(서버 연결·토큰·MCP·콘솔 한글 출력)

관리자 정책 파일(`%ProgramData%\ncn\policy.yaml`)은 IT가 그룹 정책·배포 도구로 따로 배포(사용자는 수정 불가 권한).

### 8-3. 배포 경로·업데이트
- 경로: **사내 파일 서버에 zip을 올리고 받아 가는 단순 파일 전달**(결정). 폴더 예: `\\파일서버\배포\ncn\<버전>\`, 최신본은 `latest.txt`에 버전 표시
- 업데이트: `ncn --version`과 서버의 최신 버전(`/ncn/version`, 선택)을 비교해 안내만 하고 자동 교체는 안 함(폐쇄망·권한 문제 회피)
- 제거: `uninstall.cmd`(폴더·PATH 정리, `.continue`는 남김)

### 8-4. Windows 7 사전 조건

|---|---|---|---|
| 3.9 | `list[str]`·`dict[str,int]` 실행 중 사용, `str.removeprefix`, dict `\|` 합치기, `functools.cache` | 많음 | 주석 안에서는 `from __future__ import annotations`로 그대로, 실행 중엔 `typing.List`, 자르기 함수, `{**a, **b}`, `lru_cache(None)` |
| 3.10 | `match` 문, `X \| None` 실행 중 사용, `zip(strict=)`, dataclass `slots/kw_only` | 보통 | if/elif, `Optional[X]`, 길이 확인 |

## 13. autocomplete · summarize · subagent 검토(2026-10-12, Continue 소스 확인)

### 13-1. autocomplete — MCP가 아니라 IDE 기능, `/v1/completions`로 직접 감
- 경로(`core/autocomplete/generation/CompletionStreamer.ts`): IDE에서 타이핑 → `supportsFim()`이면 FIM 전용 호출, 아니면 `streamComplete(prompt, raw: true)`. `provider: openai`는 `supportsFim()=false` → **`{apiBase}/completions`(옛 completions 엔드포인트)** 에 FIM 템플릿으로 만든 prompt를 보냄(`OpenAI.ts` `_legacystreamComplete`).
- **MCP·도구와 무관**. MCP 규격의 `completion/complete`는 프롬프트 인자 자동완성이라 코드 자동완성과 다른 것.
- **CLI(cn·ncn)에는 autocomplete가 없다** — IDE 확장 전용.
- 지금 우리 서버: 코드에이전트 프록시는 `/v1/chat/completions`만 있음 → **autocomplete 역할을 주면 404**. 쓰려면 (1) 프록시에 `/v1/completions` 전달 추가 (2) `llm_server`에 `/v1/completions` → Ollama `/api/generate`(suffix) 변환 추가 (3) **FIM을 지원하는 빠른 코드 모델**(응답 수백 ms 필요 — 26B 대화 모델은 느리고 FIM 지원 여부도 확인 필요)을 autocomplete 역할로 따로 등록.

### 13-2. summarize — 의도는 "대화 요약"이 맞지만 실제로는 안 쓰임
- 역할을 안 적은 모델의 기본 역할 = **`[chat, summarize, apply, edit]`**(`loadYaml.ts` 280줄) — 설정 화면에서 보이는 "4가지"가 이것.
- 그러나 IDE의 대화 압축(`core.ts` `conversation/compact`)은 **chat 모델**을 쓰고, 모델 선택 코드에는 "summarize not implemented yet" 주석. cn 압축도 chat 모델(5-5).
- → ncn은 cn과 같게 chat 모델로 압축. (확장: summarize 역할 모델이 있으면 그것으로 압축하는 옵션 — 기본 꺼짐)

### 13-3. subagent — cn 동작
- 하위 에이전트 = **`roles: [subagent]`인 모델**. 이름 = `name`, 설명·지시 = `chatOptions.baseSystemMessage`(`subagent/get-agents.ts`).
- 메인 LLM이 `Subagent(description, prompt, subagent_name)` 도구를 부르면 → 같은 루프를 **별도 대화**로 실행 → 최종 답 + `<task_metadata>status: completed|failed</task_metadata>`만 메인에 돌려줌(`subagent/executor.ts`).
- 하위 에이전트의 시스템 메시지 = 메인 시스템 메시지 + `baseSystemMessage`. **권한은 전부 허용**(cn 주석 "allow all tools for now").
- 메인이 Subagent를 한 응답에 여러 번 부르면 도구 병렬 실행 규칙(5-2)대로 **동시에** 돈다. 단 실행 중 전역 서비스(시스템 메시지·권한)를 바꿔 끼우는 구조라 **동시 실행 시 충돌 가능성**(P0 확인).

### 13-4. 속도 이점이 생기는 조건
턴 하나 시간 ≈ **입력 처리(prefill, 입력 토큰에 비례)** + **출력 생성(decode, 출력 토큰에 비례)** + 도구 실행.
| 이점 | 원리 | 조건 |
|---|---|---|
| ① 메인 대화를 작게 유지 | 탐색(Read·Search 결과 수천~수만 토큰)을 하위 대화에서 하고 요약 1천 토큰만 메인에 → 이후 메인의 매 턴 입력이 작아짐, **압축(요약 호출 1회 + 정보 손실)도 줄어듦** | 탐색·로그가 큰 긴 작업. 32k 컨텍스트에서 효과 큼. 서버의 프리픽스 캐시가 있으면 prefill 절감분은 줄어듦 |
| ② 동시 실행 | 독립 조사 2~3개를 동시에 | **LLM 서버가 동시 요청을 처리해야 함**(vLLM은 배치 처리 O, Ollama는 `OLLAMA_NUM_PARALLEL`, 외부 FastAPI가 순차 처리면 이점 0) |
| ③ 작은 모델 | 탐색·로그 요약은 작은 빠른 모델로 | 폐쇄망에 작은 모델을 추가로 띄울 수 있어야 함 |
| 손해 | 하위 대화마다 시스템 메시지·도구 정의를 다시 보냄 + 왕복 증가 + 요약 과정의 정보 손실 | **짧은 작업은 오히려 느려짐** |
예(가정: prefill 2,000토큰/초): 탐색으로 16k 토큰이 쌓인 뒤 수정·테스트 턴이 6번 이어지면, 메인에 16k가 남아 있을 때 약 96k 토큰을 추가로 처리(≈48초). 하위 에이전트로 요약 1k만 남기면 이 부분이 거의 사라지고 압축도 피함. 숫자는 서버 성능에 따라 다르므로 **측정으로 확인**(13-6).

### 13-5. 추천 하위 에이전트 구성
| 이름 | 하는 일 | 도구(ncn에서 제한) | 돌려주는 것 | 속도 이점 |
|---|---|---|---|---|
| **explorer**(탐색) | "X는 어디서 처리하나", 영향 범위 조사 | Read·List·Search + MCP `search_code`·`search_docs` (읽기 전용) | 경로·함수·줄 범위·근거 몇 줄(1천 토큰 이내) | ①②③ 모두 — 가장 효과 큼, 영역별로 2~3개 동시 |
| **runner**(빌드·테스트) | 빌드·테스트 실행 후 실패 분석 | Bash(허용 목록: 테스트·빌드 명령만) + Read | 실패한 테스트·오류 위치·원인 요약 | ① 큰 로그를 메인에서 격리 |
| (선택) **docs**(규칙 조회) | 사내 규칙·가이드 확인 | `search_docs`·Read | 적용할 규칙 요약 | ① — explorer에 합쳐도 됨 |
| 비추천: 병렬 수정·리뷰어 | — | — | — | 수정 충돌·승인 화면 혼란 / 리뷰는 시간이 늘어남 |

### 13-6. ncn 구현 방향
- **설정은 cn 호환**: `roles: [subagent]` 모델 + `chatOptions.baseSystemMessage` → Continue 설정 그대로.
  ```yaml
  - name: explorer
    provider: openai
    model: gemma4-26b-32k:latest        # 작은 모델이 있으면 그것으로
    apiBase: http://localhost:8200/v1
    apiKey: ${{ secrets.CODEAGENT_TOKEN }}
    roles: [subagent]
    chatOptions:
      baseSystemMessage: 코드 탐색 전담. 파일을 수정하지 않는다. 결과는 경로·함수·줄 범위와 근거만 1000토큰 이내로.
  ```
- **[추가] 하위 에이전트별 도구 제한·동시 실행 수·결과 길이 상한** — cn은 전부 허용. Continue가 모르는 키라 별도 파일 `~/.continue/ncn.yaml`에 둔다(Continue 설정 검증에 걸리지 않게).
- **[추가] 하위 대화를 독립 객체로** 실행(전역 상태 바꿔 끼우기 없음) → 동시 실행 안전.
- **측정**: 골든 작업으로 하위 에이전트 있음/없음 비교 — 걸린 시간, 총 토큰, 메인 최대 컨텍스트, 압축 횟수, 성공률. 서버 동시 처리 수(1/2/4)별로.
- 단계: P3(압축·MCP) 이후 **P3.5**로 진행.
