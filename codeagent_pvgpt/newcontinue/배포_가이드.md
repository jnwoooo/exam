# ncn 배포 가이드(관리자용)

ncn 실행 파일은 **GitHub Actions에서 빌드**한다. macOS에서는 Windows용 exe를 만들 수 없기 때문이다(PyInstaller는 교차 빌드가 안 됨).
현장 PC(폐쇄망 Windows 10 1909+/11)에는 아무것도 설치하지 않는다. 파일 서버의 zip만 받아 `install.cmd`를 실행한다.

```
[개발 PC] ─커밋·푸시─▶ GitHub ─Actions(ncn.yml)─▶ 아티팩트/릴리스 zip
                                                    │ ① 내려받기 ② 해시 확인
                                                    ▼
                                  [반입] 사내 파일 서버 \\파일서버\배포\ncn\<버전>\
                                                    │ ③ 현장 PC 가 복사 → install.cmd → ncn --doctor
                                                    ▼
                         [현장 PC] 결과(doctor.json 등) ─반출─▶ Claude Code on the web(수정) ─▶ 다시 푸시
```

---

## 1. 푸시하고 빌드 확인

| 할 일 | 방법 |
|---|---|
| 푸시 | `git push` — `codeagent_pvgpt/newcontinue/**`가 바뀐 푸시면 워크플로 `ncn`이 자동으로 돈다 |
| 손으로 실행 | GitHub → Actions → **ncn** → Run workflow(차등 시험 parity 켜기/끄기 선택) |
| 결과 보기 | Actions → 해당 실행 → job 목록 |

job별 의미:

| job | 내용 | 실패하면 |
|---|---|---|
| test (3 OS × py3.14·3.10) | `uv run pytest -q` | Windows 실패는 결과를 그대로 둔다(빨간색). 웹 세션에서 고칠 거리 — 아티팩트 `pytest-*`(JUnit XML) |
| parity | cn(5522c6f) 빌드 후 같은 시나리오로 cn·ncn 비교 | 아티팩트 `parity-out`(시나리오별 `diff.txt`), 실행 화면 Summary에 요약 |
| build (windows-x64) | **필수**. PyInstaller → zip → 스모크 시험 → **설치·제거 시험**(install.cmd /q, PATH, .env, uninstall) | 이 zip은 반입하지 않는다 |
| build (windows-arm64) | 선택(실패해도 전체 통과). arm64 PC용 | x64 zip으로 대신(arm64 Windows는 x64를 에뮬레이션으로 실행) |
| build (macos-arm64, linux-x64) | 개발·시험용 | 현장과 무관 |
| release | 태그 `ncn-v*`일 때만. zip·sha256을 GitHub Release에 첨부 | — |

## 2. 아티팩트 내려받기

**방법 A — 아티팩트(평소)**: Actions → 실행 → 아래 Artifacts에서 `ncn-<버전>-windows-x64` 받기(90일 보관). 받은 파일은 zip 안에 zip이 든 형태다(GitHub가 한 번 더 묶음). 한 번 풀면 아래가 나온다.

```
ncn-0.0.1-windows-x64.zip          ← 반입할 파일
ncn-0.0.1-windows-x64.zip.sha256   ← 해시
build_info.json                    ← 버전·커밋·크기
smoke.json                         ← 스모크 시험 결과(시작 시간 포함)
```

gh CLI를 쓰면: `gh run list -w ncn` → `gh run download <실행 id> -n ncn-0.0.1-windows-x64`

**방법 B — 릴리스(배포 확정본)**:
1. `ncn/__init__.py`의 `__version__`을 올린다(예: `"0.1.0"`) → 커밋·푸시.
2. 태그: `git tag ncn-v0.1.0 && git push origin ncn-v0.1.0` (태그 버전 ≠ `__version__`이면 build가 실패한다).
3. GitHub → Releases → `ncn-v0.1.0`에서 zip과 `SHA256SUMS.txt` 받기(기간 제한 없음).

**해시 확인**(반입 전·후 각각):
```powershell
Get-FileHash .\ncn-0.1.0-windows-x64.zip -Algorithm SHA256    # 값이 .sha256 파일의 앞부분과 같아야 함
```
```bash
shasum -a 256 -c ncn-0.1.0-windows-x64.zip.sha256              # macOS
```

## 3. 파일 서버 배치

```
\\파일서버\배포\ncn\
├─ latest.txt                       ← 최신 버전 한 줄(예: 0.1.0). 현장 사용자는 이것만 보고 폴더를 고른다
├─ 0.1.0\
│  ├─ ncn-0.1.0-windows-x64.zip
│  ├─ ncn-0.1.0-windows-x64.zip.sha256
│  ├─ ncn-0.1.0-windows-arm64.zip   (빌드됐을 때만)
│  ├─ ncn-0.1.0-windows-arm64.zip.sha256
│  ├─ ncn-vs-0.1.0.vsix             (VS 확장 — ncn-vsix 워크플로 산출물, 있으면)
│  └─ 변경사항.txt                   (선택: 이번 버전에서 바뀐 점)
└─ 0.0.1\ …                          ← 이전 버전은 되돌리기용으로 남긴다
```

- `latest.txt`: 버전 숫자 한 줄만(`0.1.0` + 줄바꿈). 폴더를 다 올린 **뒤에** 마지막으로 바꾼다(올리는 중에 받아 가는 것 방지).
- 사용자 권한: 읽기 전용. 쓰기는 관리자만.
- ncn은 자동 업데이트를 하지 않는다(계획 8-3). 사용자는 `ncn --version`과 `latest.txt`를 비교해 새 zip을 받는다.

## 4. 현장 PC 설치·확인

1. `\\파일서버\배포\ncn\<latest.txt 버전>\ncn-<버전>-windows-x64.zip`을 내 PC(예: `D:\설치\`)로 복사.
2. zip 속성 → **차단 해제** 체크(있을 때) → 압축 풀기.
3. 압축 푼 폴더의 `install.cmd` 실행(관리자 권한 필요 없음).
   - 서버 주소(예 `http://10.1.2.3:8200`) — `%USERPROFILE%\.continue\config.yaml`이 **없을 때만** 묻는다.
   - 개인 토큰(`ca-...`) — `%USERPROFILE%\.continue\.env`에 `CODEAGENT_TOKEN=`으로 저장. 이미 있으면 Enter로 유지.
4. 마지막에 `ncn --doctor` 표가 나온다. **새 명령 창**을 열어 한 번 더:
   ```bat
   ncn --version
   ncn --doctor
   ```
5. 표 읽는 법:

| 항목 | OK 조건 | 실패 시 먼저 볼 것 |
|---|---|---|
| 버전 | 늘 OK(정보) | — |
| 내장 자료 | 토큰 순위표 해시 일치 | zip 손상 → 다시 받기 |
| 설정 파일 | config.yaml 읽힘 | YAML 탭·들여쓰기 |
| 개인 토큰 | .env 에서 찾음(앞 3글자만 표시) | install.cmd 다시 실행 |
| chat 모델 | apiBase·apiKey 채워짐 | 토큰 없음 |
| 서버 연결 | `GET /v1/models` 200 | 주소·방화벽·401(토큰) |
| MCP <이름> | 접속·도구 n개 | `/mcp` 주소·토큰 |
| 콘솔 한글 | 한글 인코딩 가능 | 글꼴(돋움체 등) |
| rg(검색) | 경고여도 정상 동작 | — |
| PATH | 새 창에서 ncn 잡힘 | 창 다시 열기 |

6. Visual Studio: 확장(VSIX)이 있으면 확장 설치. 없으면 README.txt 3장대로 "외부 도구" 등록.

묻지 않는 일괄 설치(배포 도구·로그온 스크립트):
```bat
set NCN_SERVER=http://10.1.2.3:8200
set NCN_TOKEN=ca-...
\\파일서버\배포\ncn\0.1.0\풀어둔폴더\install.cmd /q
```

업데이트: 새 zip을 풀고 `install.cmd` 다시(설정·토큰 유지). 제거: `%LOCALAPPDATA%\ncn\uninstall.cmd`(`.continue`는 남김).

## 5. 문제가 생기면 — Claude Code on the web에 전달

현장 PC는 인터넷이 없으므로 결과를 파일로 저장해 반출 절차를 거쳐 옮긴다.

**① 현장에서 모을 것**
```bat
cd D:\work\문제가난저장소
ncn --doctor --format json > %USERPROFILE%\Desktop\doctor.json
ncn --version > %USERPROFILE%\Desktop\ncn_version.txt
rem 문제가 난 명령을 --verbose 로 다시 실행해 출력 전체를 저장(stdout·stderr)
ncn -p "문제가 난 질문" --verbose > %USERPROFILE%\Desktop\run.txt 2>&1
```
- doctor.json의 토큰은 앞 3글자와 길이만 들어 있다. run.txt에는 사내 코드 조각이 있을 수 있으니 반출 규정을 확인하고, 필요하면 코드 부분을 지운다.
- 함께 적을 것: Windows 버전(`winver`), VS 버전, 무엇을 했고 무엇을 기대했는지, 화면 캡처(한글 깨짐 등).

**② 웹 세션에 전달**(둘 중 하나)
- 바로 붙여 넣기: Claude Code on the web 새 세션에서 "현장 결과" + 위 파일 내용 붙여 넣기.
- 저장소에 올리기: `codeagent_pvgpt/newcontinue/field_reports/<날짜>_<주제>/`에 파일을 넣어 커밋·푸시 → 웹 세션에 "field_reports/<폴더> 보고 고쳐줘".

**③ 웹 세션이 하는 일**(CLAUDE.md "현장 시험 결과를 고칠 때")
- 재현 가능한 것은 먼저 실패하는 시험(`tests/`·`parity/scenarios/`)을 만들고 고친다 → 푸시 → 이 가이드 1장부터 다시.
- 현장에서만 확인되는 수정이면 "무엇을 확인할지"를 답에 적는다 → 새 zip으로 그 항목만 확인.

## 6. CI에서 확인되는 것 / 현장에서만 확인되는 것

| 항목 | CI(Windows 러너) | 현장 PC |
|---|---|---|
| exe가 뜨는지·`--version`·`-p`(가짜 LLM)·`--stdio` initialize·`--doctor` | ○(스모크) | ○ |
| install.cmd/uninstall.cmd — 복사·PATH(중복 없음)·.env·제거 | ○(조용한 모드) | ○(대화형 입력·한글 표시) |
| 실제 서버(:8200 /v1·/mcp)·토큰·사내 인증서·프록시 | ✗ | **○** |
| 사내 백신·SmartScreen·그룹 정책(PowerShell 제한) | ✗ | **○** |
| 한국어 Windows(cp949 콘솔)·VS 2022 연동 | ✗(영문 러너) | **○** |

## 7. 빌드를 로컬에서 돌릴 때(참고)

```bash
cd codeagent_pvgpt/newcontinue
sh packaging/build_unix.sh dist --smoke            # macOS·Linux: dist/ncn/ncn + zip + 스모크 시험
```
```powershell
.\packaging\build_win.ps1 dist -Smoke              # Windows(uv 필요): dist\ncn\ncn.exe + zip
```
- PyInstaller는 프로젝트 의존성이 아니다. 스크립트가 `uv run --with pyinstaller`로 빌드 때만 얹는다.
- 결과 폴더 `dist/`는 커밋하지 않는다.
