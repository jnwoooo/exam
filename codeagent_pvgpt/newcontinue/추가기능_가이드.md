# ncn 추가 기능 가이드

> cn(Continue CLI)에 없는 ncn 추가 기능(계획 6장 E1~E8)의 설정·동작·끄는 법. ncn 전용 설정은 `~/.continue/ncn.yaml`, 관리자 정책은 `policy.yaml`(E1).

## E5 반복 상한·반복 실패 감지

cn에는 한 턴의 반복 상한이 없다(모델이 도구를 계속 부르면 끝없이 돈다). ncn은 기본으로 두 가지를 본다.

| 검사 | 기본값 | 걸리는 때 |
|---|---|---|
| 반복 상한 | 50회 | 한 턴(사용자 메시지 하나)에서 LLM 호출이 50번이 됐을 때, 51번째 호출 직전 |
| 반복 실패 | 3회 | 같은 도구 + 같은 인자(키 순서 무시한 JSON)가 3번 연속 실패했을 때, 다음 호출 직전 |

- 실패 = 도구 오류(없는 도구·인자 누락·사전 처리 실패·실행 오류). 권한 거부는 실패로 세지 않는다. 다른 호출이 성공하면 연속이 끊긴다.
- 압축 요약 호출, Subagent 하위 대화는 세지 않는다.

**설정** — `~/.continue/ncn.yaml`(Continue config.yaml 아님)
```yaml
loop:
  max_iterations: 50          # 0 = 반복 상한 끔
  repeat_failure_limit: 3     # 0 = 반복 실패 감지 끔
```
관리자 정책(`policy.yaml`, E1)에 `max_iterations: 30` 이 있으면 그 값이 넘을 수 없는 상한이다. 사용자가 `0`으로 꺼도, "계속"을 골라도 30번에서 멈춘다(묻지 않음).

**걸리면**
| 실행 방식 | 동작 |
|---|---|
| 대화형(`ncn`) | "계속 / 멈춤"을 묻는다(AskQuestion과 같은 고르기). Esc = 멈춤. "계속"이면 다시 50번(또는 연속 실패 초기화) |
| ACP(`ncn --stdio`, VS 확장) | 같은 질문을 AskQuestion과 같은 방식으로 — elicitation(form) → `_ncn/ask` → `session/request_permission`(선택지 "계속"·"멈춤") 순 |
| 헤드리스(`ncn -p`) | 묻지 않고 턴을 끝낸다. 지금까지의 응답은 stdout, 안내 한 줄은 stderr, **종료 코드 3** |

멈추면 화면에 `ncn: …에 걸려 이번 요청을 멈췄습니다` 안내가 나온다. 대화 기록은 그대로 남으므로 다음 메시지로 이어서 지시할 수 있다.

**끄는 법**: 위 두 값을 `0`으로. `NCN_CN_COMPAT=1`이면 둘 다 꺼진다(cn과 같음, 관리자 정책 상한도 적용 안 함). 요청 본문(도구 목록·시스템 메시지)은 켜고 꺼도 같다.

| 종료 코드(헤드리스) | 뜻 |
|---|---|
| 0 | 정상(권한 거부로 턴이 끝나도 0 — cn과 같음) |
| 1 | 오류(cn과 같음) |
| 2 | ncn 미구현 옵션 |
| **3** | **[E5] 반복 상한·반복 실패로 멈춤** |
| 130 | Ctrl+C |

## E6 감사 기록

무엇을 했는지 PC에 남기고, 원하면 코드에이전트 서버로 보낸다. **파일 내용·코드 원문·도구 결과 글·응답 글은 남기지 않는다.**

**로컬 파일** — `~/.continue/ncn-audit/YYYY-MM-DD.jsonl`(날짜는 UTC). 한 줄에 사건 하나.
```json
{"id":"…32자…","ts":"2026-10-30T01:02:03.456Z","session":"<세션 id>","ui":"headless","mode":"normal","kind":"tool_call","tool":"Bash","tool_call_id":"call_0_0","args":{"command":"git status","keys":["command"]}}
```
| 공통 필드 | 뜻 |
|---|---|
| id | 사건 id(서버 중복 저장 방지) |
| ts | 시각(UTC) |
| session | 세션 id(`~/.continue/sessions/<id>.json`과 같음) |
| ui | `headless` / `interactive` / `acp` |
| mode | 권한 모드 `normal` / `plan` / `auto` |

| kind | 추가 필드 |
|---|---|
| turn_start / turn_end | turn_end: aborted, stopped_by_rejection, loop_guard(E5 이유), error(첫 줄) |
| tool_call | tool, tool_call_id, args = **경로**(filepath·file_path·dirpath·path)·**명령 첫 줄**·URL(질의 제거)·skill/subagent 이름 + 인자 이름 목록(keys)만 |
| permission | tool, decision(allow/ask/exclude), by(`policy` 정책표, `bash_security` Bash 위험 판정, `dynamic`, 또는 E1·E2가 남긴 출처) |
| approval | tool, choice(allow/reject), by=`user` — 사용자가 승인 창에서 고른 것 |
| tool_result / tool_error | status(done/canceled) / error 첫 줄 |
| usage | model, prompt_tokens, completion_tokens, total_tokens |
| retry / system | LLM 재시도(오류 첫 줄) / 압축 안내(압축 전 토큰 수)·E5 안내 첫 줄 |
| loop_guard | reason(max_iterations·repeat_failure·policy_max_iterations), decision(continue/stop) |

명령 첫 줄의 `token=…`, `password=…`, `Bearer …` 모양 값은 `***`로 가린다.

**서버 전송(선택)** — `~/.continue/ncn.yaml`
```yaml
audit:
  enabled: true                       # false = 로컬 기록·전송 모두 끔
  server: "http://<코드에이전트 서버>:8200"
  token_env: CODEAGENT_TOKEN          # 개인 토큰이 든 환경변수(없으면 ~/.continue/.env 에서 찾음)
  batch: 20                           # 몇 건씩 묶어 보낼지
```
- 보낼 사건은 `ncn-audit/outbox.jsonl`에 먼저 쌓고, 백그라운드에서 20건이 모이거나 턴이 끝날 때 `POST <server>/audit/events`로 보낸다. 대화는 기다리지 않는다.
- 서버가 꺼져 있거나 토큰이 틀리면 outbox에 그대로 남고, 다음 전송(다음 턴·다음 실행)에 다시 보낸다. 서버는 같은 id를 한 번만 저장한다.
- 끝날 때 최대 3초 기다려 마지막 것을 보낸다(못 보내면 다음 실행이 보냄).
- 서버 쪽: `/admin` 화면 아래쪽 "ncn 감사" 표 — 사용자별(세션·턴·도구 호출·거부·오류·반복 멈춤·토큰), 도구별(호출·승인 요청·거부·오류), 최근 사건 30개. 거부 = 정책 금지(exclude) + 사용자 거부(reject).

관리자 정책(`policy.yaml`)에 `audit:` 절이 있으면 그 값이 우선이고, 사용자가 `enabled: false`로 꺼도 켜진다.

**끄는 법**: `audit: {enabled: false}`(관리자 정책에 audit이 없을 때). `NCN_CN_COMPAT=1`이면 꺼진다. 요청 본문에는 영향이 없다.

## E3 인코딩·줄바꿈 보존

cn은 모든 파일을 UTF-8로 읽고 UTF-8로 쓴다. 그래서 Visual Studio의 CP949(한국어 기본) 소스는 깨진 글(�)로 읽히고, 고치면 UTF-8로 덮어써져 원본이 망가진다. ncn은 디스크 파일의 인코딩을 판별해 읽고, 같은 형식으로 되돌려 쓴다.

| 단계 | 판별 순서 |
|---|---|
| 1 | UTF-8(BOM 있음/없음) — 엄격 해석이 되면 |
| 2 | UTF-16 BOM(LE/BE) |
| 3 | `fallback` 인코딩(기본 CP949) — 엄격 해석이 되면 |
| 4 | 그래도 안 되면 cn처럼 UTF-8(대체 문자 �) |

| 도구 | 동작 |
|---|---|
| Read | 판별해 해석한 글을 cn과 같은 형식(`Content of …`)으로. 줄바꿈(`\r\n`)·BOM(글 앞 U+FEFF)은 cn처럼 글에 그대로 |
| Edit·MultiEdit | 파일에 CRLF가 있으면 LF로 맞춰 비교·치환 → 모델이 LF로 준 `old_string`도 맞는다. 결과는 원래 줄바꿈으로 |
| Write(기존 파일) | 새 내용을 원래 파일의 줄바꿈으로 맞춰 씀 |
| 저장(공통) | 원래 인코딩·BOM·줄바꿈(CRLF/LF, 섞여 있으면 많은 쪽)으로 |
| 새 파일 | cn과 같게 UTF-8, 받은 글 그대로 |

- CP949로 표현할 수 없는 글자(이모지 등)를 넣으려 하면 파일을 건드리지 않고 오류를 모델에게 돌려준다(`… is encoded in CP949 and the new content contains characters that CP949 cannot represent: '😀' (U+1F600) …`).
- 순수 UTF-8·LF 파일은 읽고 쓰는 바이트가 cn과 완전히 같다(차등 시험 그대로).
- VS 확장(ACP `fs/*` 위임) 경로는 VS가 인코딩을 관리하므로 인코딩 변환을 하지 않는다. CRLF 맞춤(Edit의 LF 비교)은 글 수준이라 그대로 적용된다. 위임이 실패해 디스크로 쓰게 되면 그때는 위 규칙.

**설정** — `~/.continue/ncn.yaml`
```yaml
encoding:
  preserve: true      # 기본 true. false = cn처럼 UTF-8 가정
  fallback: cp949     # UTF-8이 아닐 때 시도할 인코딩(파이썬 코덱 이름: cp949, euc-kr, shift_jis …)
```
**끄는 법**: `preserve: false` 또는 `NCN_CN_COMPAT=1`. 요청 본문(도구 목록·설명)은 켜고 꺼도 같다.

## E4 백업과 /undo

Write·Edit·MultiEdit가 파일을 쓰기 직전 원본을 백업한다. 승인하고 나서 "괜히 고쳤다" 싶으면 `/undo`로 되돌린다.

| 항목 | 내용 |
|---|---|
| 위치 | `~/.continue/ncn-backup/<세션 id>/<순번>_<경로 해시>`(원본 바이트) + `.json`(경로·도구·시각). 세션 id는 `~/.continue/sessions/<id>.json`과 같다 |
| 왜 전역 폴더 | 작업 폴더의 `.continue/`는 규칙 파일 때문에 저장소에 커밋되는 경우가 많다 — 백업(코드 사본)이 git·솔루션 탐색기에 섞이지 않게 |
| 새 파일 | "없었음"으로 기록 → 되돌리면 그 파일을 지운다 |
| 정리 | 세션당 최대 50개(넘으면 오래된 것부터), 30일 넘게 안 바뀐 세션 폴더는 지움 |

| 명령 | 동작 |
|---|---|
| `/undo` | 이 세션의 **마지막** 수정을 되돌림(원본 바이트 그대로 — 인코딩·BOM·줄바꿈까지). 다시 `/undo`하면 그 앞 수정 |
| `/undo list` | 백업 목록(최근 것부터) |

| 실행 방식 | 동작 |
|---|---|
| 대화형(`ncn`) | 슬래시 명령. 결과 글은 대화 기록에 system 메시지로 남아 모델도 되돌린 것을 안다 |
| ACP(`ncn --stdio`, VS 확장) | 질문 글로 `/undo`·`/undo list`를 보내면 LLM 호출 없이 처리하고 결과를 응답 글로 준다. IDE 위임 중이면 되돌림도 IDE 쓰기 요청(VS에서 Ctrl+Z 가능). 새 파일 삭제는 디스크에서 |
| 헤드리스(`ncn -p`) | 백업만 남긴다. 나중에 `ncn --resume`(대화형)이나 ACP `session/load`로 같은 세션을 열어 `/undo` |

- 수정한 뒤 파일이 또 바뀌었으면(사용자가 고침 등) 되돌릴 때 "그 변경도 함께 사라졌습니다" 주의를 붙인다.
- 백업에 실패해도(권한 등) 수정은 막지 않는다(로그 경고만).

**설정** — `~/.continue/ncn.yaml`
```yaml
backup:
  enabled: true          # 기본 true
  max_per_session: 50    # 세션당 남길 백업 수
  keep_days: 30          # 이보다 오래된 세션 백업 폴더는 지움
```
환경변수 `NCN_BACKUP_DIR`로 백업 폴더를 바꿀 수 있다(시험용).

**끄는 법**: `enabled: false` 또는 `NCN_CN_COMPAT=1`(이때 `/undo`는 cn처럼 일반 글로 LLM에 간다). 요청 본문에는 영향이 없다.

## E1 관리자 정책 파일

관리자가 PC마다 강제할 권한 규칙. 사용자 `permissions.yaml`·CLI `--allow`·`--auto`·plan/auto 모드보다 **위**에 있다. 헤드리스·대화형·ACP(VS 확장)·Subagent 하위 대화 모두 적용.

| 항목 | 내용 |
|---|---|
| 위치 | Windows `%ProgramData%\ncn\policy.yaml`(보통 `C:\ProgramData\ncn\policy.yaml`), 그 밖 `/etc/ncn/policy.yaml` |
| 시험용 | 환경변수 `NCN_POLICY_FILE=<경로>` — **시스템 위치에 파일이 있으면 무시**(사용자가 정책을 바꿔 끼우지 못하게) |
| 인코딩 | UTF-8(BOM 있어도 됨 — 메모장 저장 그대로), CRLF 가능 |
| 없으면 | cn과 같은 동작 |

```yaml
# C:\ProgramData\ncn\policy.yaml
exclude:                      # 금지 — 무엇으로도 못 바꿈(auto 모드에서도). 도구 목록에서도 빠짐
  - Fetch
  - mcp_*                     # 글롭
  - Bash(curl*)               # Bash 명령 패턴 — 'cd x && curl …'처럼 이어 붙인 조각도 검사
ask:                          # 묻기 — --auto·auto 모드에서도 묻는다(사용자가 exclude 한 것은 exclude 그대로)
  - Write(*.sql)              # 인자 이름은 실제 도구 인자(Write·Read=filepath, Edit·MultiEdit=file_path, List=dirpath, Search=pattern, Fetch=url)
allow:                        # 미리 승인 — 기본표의 ask 만 allow로(사용자가 직접 정한 ask·exclude, plan 모드 금지는 그대로)
  - Read
force_ask:                    # E2 형식 위험 규칙 — 모든 모드·NCN_CN_COMPAT 에서도 ask
  paths: [".github/", "*.sln"]
  commands: ["git push*"]
risk:                         # E2 규칙 추가(사용자 규칙처럼 --auto 에서는 꺼짐)
  commands: ["kubectl delete*"]
deny_modes: [auto]            # 금지 모드(auto·plan). --auto 로 시작하면 실행 거부, Shift+Tab 순환은 건너뜀, ACP 전환은 오류 응답
secrets:                      # E7 — 아래 절
  enforce: true
max_iterations: 30            # E5 반복 상한(넘을 수 없는 상한)
audit: {server: "http://<서버>:8200"}   # E6 감사 기록 전송
```

| 판정 순서(첫 일치) | 결과 |
|---|---|
| 1. 정책 `exclude` | exclude |
| 2. 정책 `ask` | ask(사용자 exclude 면 exclude) |
| 3. 정책 `allow` | 사용자 판정이 기본표 ask 일 때만 allow |
| 4. `force_ask` | ask(exclude 는 그대로) |
| 5. E2 위험 판정 | allow → ask(auto 모드 제외) |

- 헤드리스에서 ask = 정책 거부(cn 규칙). 모델에게 가는 글은 cn과 같은 `Command blocked by security policy`.
- **정책 파일이 깨졌으면 ncn은 실행을 거부한다**(읽기 실패·YAML 오류·키 형식 오류·없는 `NCN_POLICY_FILE` 경로). 헤드리스는 stderr 오류 + 종료 코드 1, 대화형·ACP는 세션 열기 실패. 이유: 파일이 무엇을 막으려 했는지 모르므로 "쓰기·Bash만 ask"로 대신하면 Fetch·MCP 금지 등이 빠지고, 헤드리스에선 조용히 다른 동작이 된다.
- 모르는 키는 경고만(다음 판의 키와 호환). `NCN_CN_COMPAT=1`로도 정책은 꺼지지 않는다.

**끄는 법**: 관리자가 파일을 지운다(사용자는 끌 수 없음). 관리자가 `%ProgramData%\ncn` 폴더를 만들고 일반 사용자는 읽기만 되게 ACL을 건다(`ProgramData` 아래 새 폴더는 일반 사용자도 만들 수 있다).

## E2 인자 기반 위험 판정

cn 권한은 도구 단위(Write 전체 allow 등)라 "CI 파일 쓰기"·"git push"를 따로 못 막는다. ncn은 도구 인자를 보고 위험하면 **allow를 ask로 올린다**(ask·exclude는 그대로, 내리지 않음).

| 기본 규칙 | 대상 |
|---|---|
| Write·Edit·MultiEdit 경로 | CI(`.github/`, `.gitlab-ci.yml`, `azure-pipelines*.yml`, `.circleci/`, `Jenkinsfile` 등), 빌드(`*.sln`, `*.csproj`, `*.vcxproj`, `*.props`, `*.targets`, `Directory.Build.*`, `NuGet.config`, `package.json`, `pyproject.toml`, `CMakeLists.txt`, `Dockerfile` 등), 마이그레이션(`migrations/`, `*.sql`), 비밀 후보(`.env*`, `*.pem`, `*.key`) — gitignore 문법, 대소문자 무시, 작업 폴더 기준 |
| Bash 명령 | `git push`, `git reset --hard`, `git clean`, `rm -r/-rf`, `del /s`, `rd /s`, `Remove-Item -Recurse`, `msbuild /t:Publish`, `dotnet publish`, `dotnet nuget push`, `nuget push`, `npm publish`, `twine upload` — `cd x && git push`, `git -C repo push`, `bash -c "…"` 안도 잡음 |

| 실행 방식 | 걸리면 |
|---|---|
| 대화형·ACP | 승인 질문(계속 / 계속+다시 묻지 않기 / 아니오) |
| 헤드리스 | 정책 거부(`Command blocked by security policy`, cn과 같은 글) 후 턴 종료 |

- 도구 목록(요청 본문)은 바뀌지 않는다 — 실행 시점 판정만 바뀜(차등 시험 25/25 그대로).
- `--auto`·auto 모드에서는 꺼진다(사용자가 전부 허용을 골랐으므로). 관리자 `force_ask`는 남는다.
- 사용자가 그 호출을 콕 집어 허용한 규칙(`permissions.yaml`의 `Bash(git push origin main)` — "다시 묻지 않기"로 저장된 것, `--allow "Bash(git push*)"`)이면 묻지 않는다. `Write`처럼 도구 전체 허용은 위험 경로에서 여전히 묻는다.
- Subagent 하위 대화에도 적용(하위 대화에선 ask = 거부).

**설정** — `~/.continue/ncn.yaml`
```yaml
risk:
  enabled: true                # false = E2 끔
  defaults: true               # false = 기본 규칙만 끔(아래 추가 규칙은 유지)
  paths: ["deploy/", "*.tf"]   # 경로 추가(gitignore 문법)
  commands: ["terraform apply*", "kubectl delete*"]   # 명령 조각 글롭(대소문자 무시)
```
관리자 정책의 `risk`(추가)·`force_ask`(강제)도 같은 형식.

**끄는 법**: `risk: {enabled: false}` 또는 `NCN_CN_COMPAT=1`(관리자 `force_ask`는 끌 수 없음).

## E7 비밀 보호

| 보호 | 내용 |
|---|---|
| 환경변수 | Bash 자식 프로세스·MCP stdio 서버에 물려주는 환경에서 비밀 이름을 뺀다: `*_TOKEN`, `*_KEY`, `*_KEY_ID`, `*_SECRET`, `*PASSWORD*`, `*PASSWD*`, `*_PAT`, `*CONNECTION_STRING*`, `*_CREDENTIALS`, `CODEAGENT_TOKEN`, `OPENAI_API_KEY` 등(대소문자 무시). MCP 서버 설정의 `env:`에 직접 적은 값은 그대로 전달 |
| 키 파일 | Read·Edit·MultiEdit·Write 차단 목록(cn: `.env*`, `*.pem`, `*.key`, `*.pfx`, `*.p12`, `id_rsa` 등)에 더함: `id_rsa*`·`id_ed25519*` 등 변형, `*.p8`, `*.kdbx`, `.netrc`, `_netrc`, `.git-credentials`, `.npmrc`, `.pypirc`, `credentials`, `credentials.json`, `.continue/.env`. 오류 글은 cn과 같음(`Reading or Editing … is not allowed because it is a security concern. …`) |

- 뺄 비밀이 없으면 cn처럼 환경을 그대로 물려준다. 뺀 개수만 디버그 로그에 남긴다(이름·값은 안 남김).
- MCP 서버가 `GITHUB_TOKEN` 같은 환경변수를 물려받아 써야 하면 서버 설정 `env:`에 적거나 `env_allow`에 넣는다.
- Bash에서 `cat .env`처럼 파일을 직접 읽는 것은 막지 않는다(E2·승인으로 관리).

**설정** — `~/.continue/ncn.yaml`
```yaml
secrets:
  enabled: true                       # false = E7 끔
  env_patterns: ["MYCORP_*"]          # 뺄 이름 추가
  env_allow: ["GITHUB_TOKEN"]         # 예외(빼지 않음)
  block_files: ["*.license"]          # 막을 파일 추가(gitignore 문법)
```
관리자 정책 `secrets:`도 같은 키 + `enforce: true`(사용자가 끌 수 없고 사용자 `env_allow`도 무시). 관리자 패턴·파일은 사용자 것과 합쳐진다.

**끄는 법**: `secrets: {enabled: false}` 또는 `NCN_CN_COMPAT=1`(관리자 `enforce: true`면 못 끔).
