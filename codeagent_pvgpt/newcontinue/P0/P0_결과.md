## 2. ACP(Agent Client Protocol) — ncn `--stdio`에서 쓸 모양
- 전송: stdin/stdout, 줄 단위 JSON-RPC 2.0. `protocolVersion`은 정수(현재 1).
- IDE → ncn: `initialize`, `session/new`, `session/load`, `session/prompt`, `session/cancel`, `session/set_mode`
- ncn → IDE(알림): `session/update` — `agent_message_chunk`, `tool_call`, `tool_call_update`, `plan`, `current_mode_update`
- ncn → IDE(요청): `session/request_permission`, `fs/read_text_file`, `fs/write_text_file`, `terminal/*`
- 도구 호출: `toolCallId`, `title`, `kind`(read·edit·delete·move·search·execute·think·fetch·switch_mode·other), `status`(pending·in_progress·completed·failed), `content`(text / `diff{path, oldText, newText}` / terminal), `locations`, `rawInput`, `rawOutput`
- 승인 선택지 `kind`: allow_once · allow_always · reject_once · reject_always → 응답 `{"outcome":{"outcome":"selected","optionId":…}}` 또는 `cancelled`
  - cn 승인 3가지 대응: 1 계속 = allow_once, 2 계속+다시 묻지 않기 = allow_always, 3 아니오 = reject_once
- 모드: `session/new` 응답의 `modes{currentModeId, availableModes}` + `session/set_mode`. 규격에 "앞으로 Session Config Options로 대체" 예고 → **둘 다 지원**하게 어댑터로 감쌈.
- 확장: 밑줄로 시작하는 메서드·`_meta` 필드 → AskQuestion은 `_ncn/ask`로(VS 확장만 이해, 다른 IDE에는 일반 승인 요청으로 대체).
- Python SDK: `agent-client-protocol` 0.12.1(Python 3.10~3.14).

## 3. 차등 시험 — 실행 방법
```bash
cd newcontinue
# (1회) cn 빌드 — 사용자 실행
cd .ref/continue/extensions/cli && npm run build:local-deps && npm run build && node dist/cn.js --version && cd -
# cn 기준 자료 녹화
uv run python -m parity.run --cn "node .ref/continue/extensions/cli/dist/cn.js"
# P1부터: cn과 ncn 비교 → 일치 n/N
uv run python -m parity.run --cn "node .ref/continue/extensions/cli/dist/cn.js" --ncn "uv run ncn"
```
- 격리: 임시 `HOME`·`CONTINUE_GLOBAL_DIR`, Hub 주소는 죽은 주소, 자동 업데이트·텔레메트리 끔, 세션 id 고정, 깨끗한 환경변수.
- 정규화: 작업 폴더 → `<CWD>`, `Today's date:` → `<DATE>`, 헤더는 Authorization·Content-Type만, 도구 인자는 JSON으로 파싱해 비교.
- 남는 차이: cn은 시작할 때 `api.continue.dev`로 버전 확인을 보냄(끌 수 없음, 요청 본문과는 무관). 폐쇄망에서는 실패만 하고 넘어감.
- 시험 모델 이름은 `fake-model`(`gpt-5*`·`o[0-9]*`면 cn이 `/responses`로 보냄).

## 4. 현장 환경이 폐쇄망 — 개발·반입 흐름(2026-10-29 결정 반영)
```
[개발 PC macOS] ──커밋──▶ (사용자 푸시) GitHub ──▶ [Claude Code on the web: 수정]
                                     │
                                     └─ GitHub Actions(Windows 러너): ncn.exe·VSIX·오프라인 wheel 묶음 빌드 → 산출물 zip
                                                       │ 사용자가 내려받아 파일 서버로 반입
                                                       ▼
                               [현장 PC Windows 10/11 + VS 2022, 사내 LLM] 실제 시험 → 결과를 웹 세션에 전달
```
- **PyInstaller는 교차 빌드가 안 된다**(Windows용 exe는 Windows에서만). VSIX도 VS SDK가 있는 Windows에서만 빌드 → **GitHub Actions의 Windows 러너에서 빌드**(P5에서 워크플로 작성). 현장 PC에 Python·Node·VS SDK가 없어도 됨.
- 현장 결과 전달: 현장 PC는 인터넷이 없으므로 사용자가 결과(출력·`ncn --doctor`·로그)를 옮겨 웹 세션에 붙여 넣는다. 로그는 비밀값이 빠진 형태로 남게 만든다(E6·E7).
- cn 자체는 현장에 필요 없다(차등 시험은 개발 PC에서만).
